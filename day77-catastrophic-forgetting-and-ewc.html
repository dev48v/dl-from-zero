2 · THE FISHER, THREE WAYS — AND WHERE IT IS THE CURVATURE EXACTLY

The Fisher information of a classifier is an expectation over labels drawn from the model, so on a finite label set it is a closed-form sum and not something to sample. Three independent code paths compute it here: outer products of per-class gradients, the Gauss-Newton form with the class loop on the inside, and minus the Hessian of the loss whose targets are the model's own predictions. The last one is the definition doing real work — it says the Fisher is a curvature, just not the curvature of the loss anybody trains.

THE WHOLE TRADE-OFF

THE PAGE CHECKING ITSELF

running…

The network does not decay. It leaves.

A network that has learned task A and is then trained on task B loses A. The usual word for it is degradation, and the usual picture is a curve sagging. That is not what the measurement shows. After the fine-tuning run on this page the model scores 1.1139 on task A, and task B's own teacher — a network that has never seen task A and cannot do it at all — scores 1.1180 on task A. The fine-tuned model has not been damaged. It has arrived somewhere else. Whatever protects the old task has to work by keeping the weights near where they were, because there is nothing about the new task's gradient that would ever bring them back.

So the method writes down a penalty. Add to the new task's loss a term that charges for moving away from A's solution:

L_B(theta)  +  (lambda / 2) * sum_i  F_i * (theta_i - theta_i*)^2

and the whole question is what F_i should be. Elastic weight consolidation (Kirkpatrick et al., 2017) answers: the diagonal of the Fisher information, computed at A's solution.

The Fisher really is a curvature — of a loss nobody trains

The Fisher information of a classifier is an expectation over labels drawn from the model itself:

F  =  E_x  E_{y ~ q(.|x)}  [ grad log q(y|x)  grad log q(y|x)^T ]

On four classes and sixty-four inputs that expectation is a sum of 256 terms, so nothing here is sampled. Written that way it looks like a statistical object. Differentiate the log-likelihood twice and take the same expectation, though, and the term carrying the second derivative of the network is multiplied by E[e_y] - q, which is exactly zero — so the Fisher is minus the expected Hessian of the log-likelihood, at any architecture, exactly. The page checks it as an identity and gets 1.7e-16.

That is the promise and the catch in the same line. The Fisher is the curvature of the loss whose labels come from the model. The loss being trained has labels that come from the data. Cross-entropy is linear in the target, so the two Hessians differ by exactly the Hessian of a loss with target q - t: the residual. Where the model is right the residual is zero and the Fisher is the curvature; where the model is wrong it is not. On the last layer it does not matter at all, because the logits are linear in those parameters, their second derivative is identically zero, and the two matrices agree there to the bit — 1.7e-16 on that block against 0.0109 over the whole matrix.

A diagonal is not a property of a matrix

Here is the part that no amount of care with the Fisher can fix. The full matrix is a metric: change parameter coordinates by an orthogonal Q and it transforms as Q^T F Q, and the quantity d^T F d comes out the same number, to 7.2e-16 here. The diagonal of a matrix is not that kind of object. Rotate the coordinates and the diagonal of the rotated matrix is not the rotated diagonal; it is a different penalty with different consequences.

And a rotation of the parameters changes nothing about the model. Every function the network could compute, it still computes. Gradient descent transports exactly, so plain fine-tuning lands in the same place — 4.9e-15 away, which this page insists on checking against a control rather than asserting: nudge the starting point by 1e-13 and the same run ends up about 1e-13 away, so the change of basis moved it less than rounding does. The full-Fisher run is invariant too, 9.2e-14. The diagonal-Fisher run moves 1.9185, which is half the length of the entire fine-tuning move.

In a generic basis the Fisher's diagonal is nearly flat — a spread of 73× between its largest and smallest entry becomes 4.5× — so EWC in a generic basis is close to plain L2, and that is exactly where its run lands: 0.5670 from the L2 run against 1.9185 from its own. Read at matched budgets, 84.8% of what the Fisher's shape buys over a shapeless penalty of the same mass is destroyed by writing the same model down differently. The basis that makes EWC work is the one the layers happen to be written in.

Why the exact metric loses to its own approximation

If the diagonal is a crude version of the full Fisher, the full Fisher should do better. It does worse, at every budget: 0.6754 against 0.5647 at the tightest, and worse than plain L2 at three of the four.

The reason is measurable rather than mysterious. The penalty is a second-order model of the old task's loss, and a second-order model is a statement about a neighbourhood. The full Fisher has a large near-null space, so it lets the run travel a long way for very little penalty: 4.47 in weight space at a Fisher cost of 0.0584, against the diagonal's 2.35 at 0.3947. The model that permitted that predicted the old task would lose 0.0226. It lost 0.8796. The diagonal is not a better model of the curvature — it is a worse one that happens to over-charge exactly the directions the full matrix is too permissive about, and over-charging keeps the run inside the region where its own model is still true. The other rows sit between 1.04 and 1.63 on the same ratio. This is the trust-region argument, arriving through the back door.

The distinction that does not matter, and the ones that do

Almost every implementation computes the empirical Fisher — the same expression with the observed labels in place of the model's own. Textbooks are right that they are different objects; here the difference is worth 0.1% at matched budgets (0.5653 against 0.5647), and at a model that has learned the task they are bit-identical, exactly 0, because the only thing separating them is the residual.

What does matter is that the numbers are the right numbers, not just numbers of the right size. Shuffle the Fisher's entries between parameters, keeping every value and the total mass, and the frontier gets clearly worse (0.6732 at the tightest budget). Use weight magnitude with the same total mass and it is worse still (0.8087). Per parameter the Fisher is nearly perfect — it ranks the true importances at 0.997 against the exact curvature's 1.000, and both are exactly 1.000 inside the last layer — while weight magnitude scores 0.474 and gradient size 0.398, both below a coin.

So EWC works, at these settings: it wins all four budgets, ahead of plain L2, the two nulls and the full matrix. It is worth saying how narrow that statement is. Move the seed slider and the ranking changes — at two of the six seeds the shuffled null or the rotated basis takes the tightest budget. The advantage is real, it is small, and it rests on a choice of coordinates that the network does not know it has made.

What the page checks about itself

  • The teacher scores exactly zero on its own task, so the floor is a construction and not an estimate; at full overlap the two tasks are the same function and there is nothing to forget.
  • The backward pass is checked at initialisation against forward-mode dual numbers, which have no step size in them, and beats a central difference by five orders of magnitude.
  • Three code paths for the Fisher agree; the Hessian is symmetric across independently computed columns; the Hessian is affine in the target distribution, which is what makes the decomposition into Fisher plus residual exact.
  • An unbounded penalty is exactly “do not move”: the weights come back to A's solution to 1.7e-13, because the penalty is applied as a proximal step rather than as one more gradient.
  • Every invariance claim is checked against a 1e-13 nudge to the same computation, so “unchanged” means smaller than that run's own rounding, not smaller than a number somebody picked.

1 · A task with a floor you can compute

Six binary features give 64 inputs, and all 64 are used. The labels are a distribution over four classes produced by a teacher network with four hidden units, and the student has more, so a zero-excess solution provably exists. The teacher is padded into the student's shape by switching the extra units off, which is bit-exact: a zeroed row of the first layer gives tanh(0), and a zeroed column of the second multiplies it by zero.

function act(z, lin){ return lin ? z : Math.tanh(z); }
function dact(a, lin){ return lin ? 1 : 1 - a * a; }

Both the nonlinearity and its derivative live in exactly one place, so the linear twin of the whole engine is a two-token edit — which is how the independent verifier builds one, rather than trusting the flag.

2 · The Fisher, twice, on purpose

The first version accumulates outer products of the per-class gradients weighted by the model's own probabilities. The second builds the Gauss-Newton form with the class loop on the inside and never forms a per-class gradient at all.

They are the same matrix algebraically and they agree to 1.7e-16, which is what you want from two pieces of code that share nothing but a definition.

3 · Second derivatives with no step size

The Hessian is not estimated. The backward pass is run over dual numbers — forward-over-reverse — so one seed per parameter produces one exact column:

function hessCol(p, dm, X, T, lin, seed){
        gd[w3] += dzd * av[j] + dzv * ad[j];

The two triangles come from different seeds, so their agreement (2.1e-17) is a check on the second-derivative code rather than a property of it. Feed the same routine the model's own predictions as targets and it returns the Fisher, exactly; feed it the true labels and it returns the curvature of the loss being trained.

4 · The penalty is solved, not stepped

An explicit penalty gradient blows up as soon as lr * lambda * F_ii passes 2, so half of any strength sweep would be measuring an optimiser instability. The quadratic is solved instead:

function proxDiag(lr, lam, D){
  for (i = 0; i < D.length; i++) s[i] = 1 / (1 + lr * lam * D[i]);

which is stable at every strength and whose infinite-strength limit is exactly “do not move”. That limit is checked: at lambda = 1e14 the weights move 1.7e-13 and the old task's score is unchanged.

5 · Training in other coordinates

The rotation experiment is not simulated by transforming the penalty. The run is actually done in the rotated basis: the parameters are carried as u, mapped forward for every forward pass, and the gradient is mapped back.

function trainRot(p0, dm, X, T, lin, steps, lr, Q, lam, Du, refU){
    var th = matVec(Q, u), r = gradOf(th, dm, X, T, lin, null), gu = matTVec(Q, r.g);

With no penalty this has to reproduce the ordinary run exactly, and it does. With a diagonal penalty it does not, and that is the whole finding.

6 · Assertions that are identities

The checks that carry weight are the ones with no tolerance in them at all:

ck(o.fisher.teacherEmp === 0,
     "at a model that has learned the task the two Fishers are not bit-identical");
  ck(o.gauge.dLoss <= 1e-12,
     "adding the same number to every class bias changed the loss (" + o.gauge.dLoss + ")");

Where a tolerance is unavoidable it is derived rather than chosen — a multiple of the machine epsilon and the quantity's own scale, or a measured control. The invariance claims are all bounded by how far a 1e-13 nudge moves the same run, and the second-order ladder's step is searched for on a dyadic grid rather than picked, with a floor so that a leftover is never compared with the arithmetic that produced it.

7 · Everything is one file

No build step, no dependency, no network access. The engine is pure functions with no DOM, no clock and no unseeded randomness, which is what lets an independent verifier extract it and run it against oracles written the other way round.
