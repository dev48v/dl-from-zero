DeepLearningFromZero · Day 56

👥 Mixture-of-Experts Layer — a dense Transformer runs every token through the same feed-forward block, so capacity (parameters) and cost (FLOPs) are welded together: to get a smarter model you pay more per token. An MoE layer (Shazeer 2017; Switch, Fedus 2021; Mixtral, 2023) breaks that weld. It replaces the one shared FFN with N independent expert MLPs plus a tiny gating network — a single linear layer whose softmax over the experts says how much each token wants each expert. The trick is sparsity: instead of running all N experts, keep only the top-k (k = 1 in Switch, k = 2 in Mixtral), renormalize those k gate weights, and combine only those experts’ outputs — y = Σe∈top-k g̃e·Ee(x). So total parameters scale with N (a Mixtral-8x7B holds ~47B params) while the FLOPs per token stay fixed at k experts (~13B active) — more knowledge, same compute. But real hardware wants dense, equal-sized batches per expert, so each expert gets a fixed capacity C = f·(T·k / N); tokens routed to an already-full expert overflow and are dropped (they skip the layer via the residual). And a raw gate is unstable: whichever experts get picked early get trained more, get picked more — a rich-get-richer collapse onto a few experts while the rest die. The fix is an auxiliary load-balancing loss Laux = N·Σe fe·Pe (fraction of tokens dispatched × mean router probability) added to the training loss to encourage uniform expert usage. Below: feed a live stream of tokens through a real gate, watch the top-k routing, the per-expert capacity + dropped tokens, and toggle the aux loss to watch a collapsed router genuinely rebalance as the loss falls — softmax, top-k, capacity dispatch and the aux-loss gradient all implemented by hand, no libraries.

What to try: (1) Leave k=1, turn the aux loss OFF, and press new tokens a few times: the router collapses — one expert hogs the traffic, its bar shoots past the capacity tick and a pile of tokens is dropped, while other experts sit idle (max/mean load » 1, aux loss near N). (2) Now flip aux loss ON and hit auto-train: the gradient pushes the overused expert down, the bars level off, dropped tokens fall to zero and the aux-loss trace slides toward 1 — that is load balancing. (3) Raise k from 1→2 (Mixtral’s setting): each token now blends two experts and the FLOPs/token doubles while params are unchanged. (4) Shrink the capacity factor toward 0.25: even balanced routing starts dropping tokens because no expert can hold its share — capacity is a hardware budget, not a correctness knob. (5) Grow N: more parameters for the same k active per token — the whole point of sparsity.

🔨 Build it yourself

    
An MoE layer is a dense FFN split into N experts plus a tiny gate that routes each token to a few of them. We’ll build it end to end: the softmax gate, top-k selection with renormalized weights, the sparse forward that only runs the chosen experts, the fixed per-expert capacity that drops overflow, the auxiliary load-balancing loss that keeps the gate from collapsing, and one gradient step that proves it rebalances — softmax, top-k, dispatch and the aux gradient all by hand.

    
    
      
  1. 
        
    1
    The gate — a softmax over the experts
    
        
    The gate is a single linear layer W_g that maps a token to one logit per expert, then softmax turns those into a distribution: how much this token wants each expert. Numerically-stable softmax subtracts the max first; the result sums to 1.
    
        
    import numpy as np

def softmax(z):
    z = z - z.max()                 # stability, doesn't change the result
    e = np.exp(z)
    return e / e.sum()              # sums to 1

def gate(x, Wg):                    # Wg: (N_experts, d)
    return softmax(Wg @ x)          # p[e] = P(expert e | token x)
    
      
    2. 
      
  2. 
        
    2
    Top-k routing — keep the k largest, renormalize
    
        
    Sparsity is the whole point: don’t run all N experts, keep only the top-k gate entries (k=1 Switch, k=2 Mixtral). Renormalize just those k weights so they sum to 1 again — they become the mixing coefficients for combining the chosen experts’ outputs.
    
        
    def top_k(p, k):
    idx = np.argsort(p)[::-1][:k]   # indices of the k largest gate probs
    w   = p[idx]
    w   = w / w.sum()               # renormalize over the kept experts
    return idx, w                   # experts to run + their weights

# argsort picks the k largest; renorm makes the kept weights sum to 1

  3. 
        
    3
    Sparse forward — run only the chosen experts
    
        
    Each expert is an ordinary MLP. For one token, run only its k experts and take the gate-weighted sum. Because k is fixed, the FLOPs per token stay constant no matter how many experts N you add — params grow, compute does not.
    
        
    def moe_token(x, Wg, experts, k):
    p        = gate(x, Wg)
    idx, w   = top_k(p, k)
    y = np.zeros_like(x)
    for e, we in zip(idx, w):
        y += we * experts[e](x)     # only k experts actually run
    return y                        # cost ~ k experts, not N
    
      
    4. 
      
  4. 
        
    4
    Capacity — a fixed slot count that drops overflow
    
        
    Hardware wants equal, fixed-size batches per expert, so each expert gets C = f * (T*k / N) slots. Dispatch tokens in order; once an expert is full, extra tokens overflow and are dropped — they skip the layer through the residual connection. f (capacity factor) buys slack against imbalance.
    
        
    def dispatch(idxs, T, k, N, f=1.25):
    C = int(np.ceil(f * T * k / N))     # slots per expert
    load = np.zeros(N, int); kept = []
    for token_experts in idxs:          # tokens in arrival order
        keep = []
        for e in token_experts:
            if load[e] < C:
                load[e] += 1; keep.append(e)   # accepted
            # else: OVERFLOW -> dropped, token uses the residual
        kept.append(keep)
    return kept, load, C

    The auxiliary load-balancing loss
    
        
    A raw gate collapses: a few experts win, get trained more, win more. Switch adds L_aux = N * Σ f_e * P_e to the training loss — f_e is the fraction of tokens dispatched to e (a hard count), P_e the mean soft router probability for e. It is minimized (=1) exactly when usage is uniform, so it pulls the gate toward balance.
    
        
    def aux_loss(P_soft, dispatch_counts, T, k, N):
    f = dispatch_counts / (T * k)   # fraction of routed tokens per expert
    P = P_soft.mean(axis=0)         # mean router prob per expert (soft)
    return N * np.sum(f * P)        # = 1 when uniform, ~N when collapsed

  6.

    One gradient step — the gate rebalances
    
        
    The gradient flows through the soft P_e (the hard count f_e is detached). Through the softmax Jacobian it reduces to a clean rule: push the logit of an over-used expert (large f_e) down. Take a step and the aux loss falls — that is exactly what the live demo runs.
    
        
    # dL/dlogit_e = (N/T) * Σ_t p_t[e] * (f_e - Σ_j f_j p_t[j])
def aux_grad_step(logits, f, lr):
    P = np.stack([softmax(z) for z in logits])     # (T, N)
    S = P @ f                                       # per-token Σ_j f_j p_t[j]
    g = (P * (f[None,:] - S[:,None])).sum(0) * (len(f)/len(P))
    return logits - lr * g          # over-used expert's logit decreases

  7. 
        
    7
    The whole MoE layer
    
        
    Put it together for a batch: gate every token, take top-k, dispatch under capacity, run the kept experts, gate-weight the outputs, and add the aux loss to the main loss during training. Total params scale with N; FLOPs per token scale with k.
    
        
    def moe_layer(X, Wg, experts, k, f=1.25, train=False):
    T, N = len(X), len(experts)
    P = np.stack([gate(x, Wg) for x in X])          # (T, N) soft gate
    routes = [top_k(P[t], k) for t in range(T)]     # (idx, w) per token
    kept, load, C = dispatch([r[0] for r in routes], T, k, N, f)
    Y = np.zeros_like(X)
    for t,(idx,w) in enumerate(routes):
        for e, we in zip(idx, w):
            if e in kept[t]:                        # respect capacity
                Y[t] += we * experts[e](X[t])
        # dropped tokens just keep the residual (Y[t] stays 0 here)
    L_aux = aux_loss(P, load, T, k, N) if train else 0.0
    return Y, L_aux                                 # add λ·L_aux to the loss

🎉 Day 56 of DeepLearningFromZero done.
A Mixture-of-Experts layer replaces one shared FFN with N expert MLPs and a tiny softmax gate. Each token is routed to only its top-k experts (k=1 Switch, k=2 Mixtral), their gate weights renormalized and their outputs blended — so parameters scale with N while FLOPs per token scale with k, decoupling capacity from compute. Real hardware imposes a fixed per-expert capacity C = f·T·k/N, and tokens that overflow a full expert are dropped to the residual. Left alone a gate collapses onto a few experts, so an auxiliary load-balancing loss N·Σ fePe (minimized at 1 for uniform usage) is added to the training loss and its gradient pushes over-used experts down — exactly the rebalancing you watched the trace perform. That sparsity is how Switch Transformer and Mixtral-8x7B pack tens of billions of parameters while paying for only a fraction per token. 👉 Tomorrow, Day 57: Sharpness-Aware Minimization — seek flat minima to generalize better.
