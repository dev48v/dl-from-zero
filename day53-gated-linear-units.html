DeepLearningFromZero · Day 53

🚦 Gated Linear Units (GLU · GEGLU · SwiGLU) — a standard Transformer feed-forward block is dead simple: Linear → one fixed nonlinearity → Linear, where that middle activation (ReLU, GELU…) applies the same elementwise curve to every hidden unit. A Gated Linear Unit throws that single activation out and replaces it with a multiplicative valve: project the input twice, keep one branch as the raw value (xW + b), turn the other branch into a gate by squashing it, σ(xV + c) ∈ (0,1), and multiply the two element by element — out = (xW + b) ⊙ σ(xV + c). The gate decides, per unit and per input, how much of the value is allowed through: a gate near 0 shuts that feature off, a gate near 1 lets it pass. That’s a data-dependent, multiplicative interaction — an AND-like “pass this feature only when the input also says so” — which a single Linear + ReLU (an additive, per-unit curve) cannot express cheaply. The whole GLU → GEGLU → SwiGLU family is just which squashing function you put on the gate: GLU uses the sigmoid, GEGLU uses GELU, and SwiGLU uses SiLU / Swish (z·σ(z)) — the latter two are smooth, non-monotonic “self-gated” curves that (unlike sigmoid) don’t hard-cap at 1, so the gate can also scale magnitude. Noam Shazeer’s 2020 note “GLU Variants Improve Transformer” showed GEGLU/SwiGLU FFNs give the best quality-per-parameter, which is exactly why PaLM, LLaMA / 2 / 3 and Mistral all use a SwiGLU FFN — (SiLU(xW) ⊙ xV) W₂ — with the hidden width shrunk to ⅔ so the extra third matrix doesn’t inflate the parameter count. 🔨 Build it yourself

    
A gated linear unit is two linear projections glued by an elementwise product. We’ll build it piece by piece: the three activations by hand, the two projections, the GLU forward, the one-line swap to GEGLU / SwiGLU, and finally the full SwiGLU FFN with its down-projection and the ⅔ hidden-width rule that keeps the parameter count honest.

    
    
      
  1. 
        
    1
    The three gate activations, by hand
    
        
    Each variant differs only in the function on the gate. sigmoid squashes to (0,1). GELU uses the fast tanh approximation. SiLU (a.k.a. Swish with β=1) is literally z·sigmoid(z). Sanity: sigmoid(0)=0.5, GELU(0)=0, SiLU(0)=0.
    
        
    import numpy as np

def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))

def gelu(z):                       # tanh approximation (GPT-2 / BERT)
    k = np.sqrt(2.0 / np.pi)
    return 0.5 * z * (1.0 + np.tanh(k * (z + 0.044715 * z**3)))

def silu(z):                       # SiLU == Swish with beta = 1
    return z * sigmoid(z)

# gate picker for the GLU family
GATE = {"GLU": sigmoid, "GEGLU": gelu, "SwiGLU": silu}

  2. 
        
    2
    Two projections — value and gate
    
        
    Instead of one weight matrix, a GLU uses two: W makes the value branch and V makes the gate branch. Both map the input x (dim d) into the same hidden width h. This doubling of the up-projection is the whole extra cost.
    
        
    d, h = 4, 6                        # toy: input dim, hidden dim
W = np.random.randn(d, h) * 0.8    # value weights   -> (d, h)
V = np.random.randn(d, h) * 0.8    # gate  weights   -> (d, h)
b = np.random.randn(h)  * 0.3      # value bias
c = np.random.randn(h)  * 0.3      # gate  bias

def branches(x):
    value    = x @ W + b           # linear, NO activation   (h,)
    gate_pre = x @ V + c           # will be squashed         (h,)
    return value, gate_pre

  3. 
        
    3
    The GLU forward — the elementwise product
    
        
    Squash the gate branch with the sigmoid and multiply element by element (Hadamard product ⊙). Every hidden unit gets its own learned gate in (0,1): a soft, per-unit, input-dependent on/off switch on the value.
    
        
    def glu(x):
    value, gate_pre = branches(x)
    gate = sigmoid(gate_pre)       # gate in (0, 1)
    return value * gate            # elementwise product  ->  (h,)

# out = (xW + b) ⊙ σ(xV + c)
#         value          gate
# gate → 0 : that unit is shut ;  gate → 1 : value passes through

  4. 
        
    4
    GEGLU & SwiGLU — a one-line swap
    
        
    The variants change only the gate activation. Swap sigmoid for gelu to get GEGLU, or for silu to get SwiGLU. Because GELU/SiLU aren’t capped at 1, the gate can amplify as well as attenuate — empirically the best-performing FFN gates.
    
        
    def gated(x, kind="SwiGLU"):
    value, gate_pre = branches(x)
    gate = GATE[kind](gate_pre)    # sigmoid | gelu | silu
    return value * gate

glu    = gated(x, "GLU")      # (xW+b) ⊙ σ(xV+c)
geglu  = gated(x, "GEGLU")    # (xW+b) ⊙ GELU(xV+c)
swiglu = gated(x, "SwiGLU")   # (xW+b) ⊙ SiLU(xV+c)   ← PaLM / LLaMA

    The full SwiGLU FFN — and the ⅔ rule
    
        
    In a Transformer, the gated hidden goes through a third matrix W2 back to the model width. A plain ReLU FFN has 2 matrices of size d×4d; a gated FFN has 3 (W, V, W2). To keep the parameter count equal, shrink the hidden width by 2/3 — that’s LLaMA’s d_ff = 8/3·d.
    
        
    import torch, torch.nn as nn, torch.nn.functional as F

class SwiGLU_FFN(nn.Module):
    def __init__(self, d_model, mult=4):
        super().__init__()
        d_ff = int(2/3 * mult * d_model)          # 3 matrices ⇒ shrink ⅔
        self.w  = nn.Linear(d_model, d_ff, bias=False)   # value  W
        self.v  = nn.Linear(d_model, d_ff, bias=False)   # gate   V
        self.w2 = nn.Linear(d_ff, d_model, bias=False)   # down   W2

    def forward(self, x):
        gated = F.silu(self.v(x)) * self.w(x)     # SwiGLU core
        return self.w2(gated)                     # back to d_model

    Why it wins — a multiplicative valve
    
        
    A ReLU FFN applies the same curve to every unit — an additive nonlinearity. A GLU makes the nonlinearity multiplicative and data-dependent: the gate branch reads the input and decides how much of the value branch survives, an AND-like interaction that’s far cheaper to express as a product than to approximate with more ReLU units. Same FLOP budget, better loss — so modern LLM FFNs are gated.
    
        
    # plain FFN :  W2 @ relu(W1 @ x + b1) + b2      # one fixed curve / unit
# gated FFN :  W2 @ ( silu(V @ x) * (W @ x) )    # value gated by the input

# the product term  value ⊙ gate  is the key:
#   gate ≈ 0  →  route this feature OFF   (for THIS input)
#   gate ≈ 1  →  let the value THROUGH
#   gate > 1  →  (GELU/SiLU) amplify
# a single Linear+ReLU has no cheap way to make one unit depend on another.

🎉 Day 53 of DeepLearningFromZero done.
A Gated Linear Unit replaces a Transformer FFN’s single fixed activation with a multiplicative valve: project the input twice, keep one branch as the value (xW+b), squash the other into a gate, and multiply them elementwise — out = (xW+b) ⊙ act(xV+c) — so each unit is switched on or off per input. The GLU → GEGLU → SwiGLU family only swaps that gate activation (σ → GELU → SiLU/Swish); the smooth, uncapped GELU/SiLU gates let the valve amplify as well as attenuate, and Shazeer’s 2020 result made SwiGLU the FFN of choice in PaLM, LLaMA and Mistral — with the hidden width trimmed to ⅔ so the extra third matrix stays parameter-neutral. 👉 Tomorrow, Day 54: ALiBi — position without embeddings, penalising attention by token distance so a model trained short extrapolates to far longer contexts.
