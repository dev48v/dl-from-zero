DEEPLEARNINGFROMZERO · DAY 64

🧮 Group Normalization — every normalizer in this series so far differs in exactly one way: which axes it averages over. BatchNorm averages across the batch, which is why it is the only one whose output for a given image depends on the other images in the batch — and why it degrades as the batch shrinks. At N=1 with spatial dimensions it does not zero out, as is often claimed; it silently becomes InstanceNorm, computing per-channel statistics from a single image, which is a different function from the one it was training. The true collapse to identically-zero happens when the averaging set holds one element — N=1 with H·W=1, i.e. BatchNorm1d on a single sample. This page computes both cases rather than describing them. GroupNorm (Wu & He, 2018) averages over channel groups within one sample, so it is batch-size independent by construction — the same input gives the same output whether the batch holds 1 image or 64, which is asserted here to floating point. Group count G interpolates between the family: G=1 is LayerNorm, G=C is InstanceNorm, and both identities are checked numerically rather than claimed. Plus the part that actually matters in practice: BatchNorm's train/eval mismatch, which GroupNorm does not have because it has no running statistics at all.

G must divide C — the slider snaps to the nearest divisor. Every number below is computed from a real tensor by hand-written loops.

THE TWO IDENTITIES

GroupNorm is not a new idea so much as a dial. At G=1 it is LayerNorm; at G=C it is InstanceNorm. Those are exact numerical claims, so check them. 


      


    

  






  

    


      
One operation, four names, different axes


      
Every normalizer does the same three things: compute a mean and variance over some set of
      elements, subtract and divide, then apply a learned scale and shift. The only
      difference between them is which elements go into that set.


      

        
tensor shape: (N, C, H, W)

BatchNorm     → average over (N, H, W)   ... one mean per CHANNEL
LayerNorm     → average over (C, H, W)   ... one mean per SAMPLE
InstanceNorm  → average over (H, W)      ... one mean per sample per CHANNEL
GroupNorm     → average over (C/G, H, W) ... one mean per sample per GROUP

      


      
Read that list again and one line stands out: BatchNorm is the only one whose set spans
      N. Everything that follows comes from that.


      
Why crossing the batch is a problem

      
If the statistics depend on N, then the output for a given image depends on which other
      images happened to be in the batch with it. That is strange on its face and has three
      practical consequences:

      
    
        
  • Small batches give noisy statistics, so the normalization is noisy.
    • 
        
  • At N=1 with spatial dimensions, BatchNorm quietly becomes InstanceNorm —
        it still has H·W values per channel to average over, so it does not zero out, it computes a
        different function from the one it trained. This is checked numerically on the MEASURE tab.
    • 
        
  • When the averaging set really does hold one element — N=1 and H·W=1, which is
        BatchNorm1d on a single sample — every normalized value is exactly 0 and the
        layer has thrown the input away entirely.
    • 
        
  • Training and inference must use different code paths, because at inference there
        is no batch to average over.
    • 
      


      
The train/eval mismatch

      

        
BatchNorm keeps running estimates of mean and variance for
        inference. So the function computed at eval time is not the function trained. When those
        estimates are stale, or the deployment distribution differs, the model behaves differently in
        production than in validation — and model.eval() is the most consequential single
        line in a lot of PyTorch codebases for exactly this reason. GroupNorm has no running
        statistics, so there is no mismatch to get wrong.

      


      
Why groups rather than all channels

      
LayerNorm normalizes across every channel at once, which assumes all channels are
      commensurate. In a convnet they are not — an edge detector and a colour-blob detector have
      genuinely different scales, and forcing them into one distribution discards information.

      
InstanceNorm goes to the other extreme: one channel per group, which removes exactly the
      per-channel contrast that classification often depends on. Useful for style transfer, where you
      want to discard it, and poor for recognition.

      
GroupNorm sits between: related channels share statistics, unrelated ones do not. G=32 is the
      usual default, and the paper's own ablation shows the result is not very sensitive to it —
      which is a mild claim, and this page lets you move the dial and see the numbers rather than
      trusting either of us.


      
The trade, honestly

      
At large batch sizes BatchNorm still tends to win slightly on accuracy — its noise across the
      batch acts as a regularizer. GroupNorm's case is that it is flat: its accuracy
      barely moves as the batch shrinks, so at N=2 or N=1 it is far ahead. That is why detection and
      segmentation, where high-resolution inputs force tiny batches, adopted it.

      
If you train at N=256 on one machine, BatchNorm is fine. The moment memory forces you down,
      the picture inverts.


    

  






  

    


      
🔨 Build it yourself


      
1. One function, parameterised by the axes

      
Write the shared machinery once and let each normalizer say which elements it groups
      together. The whole family then differs by a single index function, which also makes the
      identities below testable instead of rhetorical.

      
// x is (N, C, HW) flattened. groupOf(n, c) says which stat-group an element joins.
function normalizeBy(x, N, C, HW, groupOf, eps = 1e-5){
  const sum = new Map(), sq = new Map(), cnt = new Map();
  for (let n = 0; n < N; n++)
    for (let c = 0; c < C; c++)
      for (let i = 0; i < HW; i++){
        const g = groupOf(n, c), v = x[(n*C + c)*HW + i];
        sum.set(g, (sum.get(g) || 0) + v);
        sq.set(g,  (sq.get(g)  || 0) + v*v);
        cnt.set(g, (cnt.get(g) || 0) + 1);
      }
  const out = new Float64Array(x.length);
  for (let n = 0; n < N; n++)
    for (let c = 0; c < C; c++)
      for (let i = 0; i < HW; i++){
        const g = groupOf(n, c), k = cnt.get(g);
        const mean = sum.get(g)/k;
        const varr = sq.get(g)/k - mean*mean;
        out[(n*C + c)*HW + i] = (x[(n*C + c)*HW + i] - mean) / Math.sqrt(varr + eps);
      }
  return out;
}


      
2. The four normalizers, as four index functions

      
const batchNorm    = (x,N,C,HW)   => normalizeBy(x,N,C,HW, (n,c) => "c" + c);
const layerNorm    = (x,N,C,HW)   => normalizeBy(x,N,C,HW, (n,c) => "n" + n);
const instanceNorm = (x,N,C,HW)   => normalizeBy(x,N,C,HW, (n,c) => n + ":" + c);
const groupNorm    = (x,N,C,HW,G) => normalizeBy(x,N,C,HW,
                       (n,c) => n + ":" + Math.floor(c / (C/G)));

      
That is the entire subject. Four one-liners over one shared implementation — and now the
      family relationships are things you can execute.


      
3. Check the identities, do not assert them

      
// G = 1  →  every channel of a sample in one group  →  LayerNorm
assertClose(groupNorm(x, N, C, HW, 1), layerNorm(x, N, C, HW));

// G = C  →  each channel its own group             →  InstanceNorm
assertClose(groupNorm(x, N, C, HW, C), instanceNorm(x, N, C, HW));

      
If either fails, the grouping index is wrong, and every later measurement is measuring
      something else.


      
4. Batch-size independence — the actual claim

      
// Take the SAME sample, put it in batches of different sizes, compare its output.
const big   = groupNorm(batchOf(sample, 32), 32, C, HW, G);
const small = groupNorm(batchOf(sample, 1),   1, C, HW, G);
assertClose(sliceSample(big, 0), sliceSample(small, 0));   // to floating point

// The same test with BatchNorm must FAIL - that is the point.
const bnBig   = batchNorm(batchOf(sample, 32), 32, C, HW);
const bnSmall = batchNorm(batchOf(sample, 1),   1, C, HW);
assert(!close(sliceSample(bnBig, 0), sliceSample(bnSmall, 0)));

      
The negative assertion matters as much as the positive one. A test that only shows GroupNorm
      is stable proves nothing unless it also shows the alternative is not.


      
5. The N=1 collapse

      
// CAREFUL. With spatial dims, N=1 does NOT zero out: BatchNorm still averages
// over H*W, so it degenerates into InstanceNorm - a different function from the
// one it trained, which is the actual bug.
assertClose(batchNorm(x, 1, C, HW), instanceNorm(x, 1, C, HW));

// The genuine collapse needs the averaging set to hold ONE element:
// N = 1 AND H*W = 1, i.e. BatchNorm1d on a single sample.
const out = batchNorm(x1, 1, C, 1);
assert(out.every(v => Math.abs(v) < 1e-6));   // input erased entirely


      
6. Verify the output is actually normalized

      
// Within each group, mean ≈ 0 and variance ≈ 1. This catches an eps applied in
// the wrong place, which otherwise looks fine and silently rescales everything.
for (const g of groups){
  assertClose(meanOf(g), 0, 1e-9);
  assertClose(varOf(g),  1, 1e-4);   // slightly under 1 because of eps
}
