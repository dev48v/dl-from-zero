DeepLearningFromZero · Day 61

✂ Pruning — a trained network is almost entirely made of weights it does not need. Not slightly over-built: the standard result, unchanged since LeCun’s Optimal Brain Damage in 1989 and reconfirmed on every architecture since, is that you can delete 90–95% of the weights of a converged model and get the accuracy back. That is a strange sentence, and the first job of this page is to make it stop being strange. Over-parameterisation is a training aid, not a deployment requirement — the extra capacity buys you a loss surface that gradient descent can actually navigate, and once it has arrived, most of it is scaffolding. So you remove it, and the whole subject is two questions: which weights, and what happens next. The cheapest answer to the first is magnitude: a weight near zero contributes almost nothing to any activation, so sort by |w| and cut from the bottom. It is a crude first-order proxy — the correct question is how much the loss would rise, which is what Optimal Brain Damage’s Hessian diagonal and movement pruning estimate properly — and yet it is startlingly hard to beat, as the random-mask control on this page shows the moment you compare them. The second question splits the field in half. Unstructured pruning zeroes individual weights: it reaches the highest sparsity and, on ordinary hardware, buys you nothing at all in speed, because a matrix full of zeros is still a dense matrix multiply. Structured pruning deletes whole neurons, channels or attention heads: the tensors genuinely shrink, the FLOPs genuinely drop, and this page proves the equivalence exactly — masking neuron j and physically deleting row j of W₁ together with column j of W₂ produce bit-identical logits. Then the part everybody gets wrong: one shot is the wrong schedule. Prune 25%, fine-tune, repeat — iterative magnitude pruning — and the network walks to 94% sparsity with no measurable loss, while a single 94% cut with the same total fine-tuning budget does visibly worse. That loop is also what produced the most-discussed result of the last decade: the Lottery Ticket Hypothesis (Frankle & Carbin, 2019) — take the surviving mask, rewind the survivors to the exact values they had at initialisation, retrain, and the tiny sub-network trains to full accuracy on its own. The claim only means anything against its controls, so this page runs all three arms live: rewound ticket, same mask with a fresh random init, and a random mask of identical size. Below, a real 144–32–3 MLP with a hand-written backward pass trains in your browser, gets pruned four different ways, healed, iterated and rewound, with every accuracy re-measured on a held-out set. 4,704 prunable weights, no libraries, 213 assertions checked in Node against brute-force top-k, closed forms and central finite differences.

The Lottery Ticket Hypothesis — and the two controls that are the actual experiment

Take the mask that iterative pruning just found. Rewind the surviving weights to the exact values they held at initialisation, throw everything the network learned away, and train the sub-network from scratch. If it reaches full accuracy on its own, that sparse sub-network plus its original init was a winning ticket — it was inside the dense model from step zero. The claim is only meaningful against its controls, so all three arms below are trained here, three seeds each, identical budget: rewound, same mask but a fresh random init, and a random mask of identical size.

—
⚠️ Read this honestly. The gap between rewind and fresh random init is the whole Lottery Ticket claim, and on a network this small it is a few points at most and moves between seeds — which is exactly what the follow-up literature found at scale. Later work (Frankle et al., Linear Mode Connectivity, 2020) showed the original rewind-to-step-0 recipe fails on larger models and has to be replaced by late rewinding to iteration k, and several replications found that random pruning followed by retraining is a much stronger baseline than the original paper implied. What is not ambiguous, on any scale, is the third bar: a random mask of the same size trains far worse. The structure the pruning found is real. Whether the initial values add anything on top of it is the part still being argued about.
The number everyone quotes, and the number that actually ships: sparsity is not speed

A 95%-sparse weight matrix on a normal GPU runs at exactly the same speed as the dense one. The zeros are still there; the kernel still multiplies them. Unstructured pruning buys compressed storage and nothing else until you have a sparse kernel that beats dense at your sparsity level — and the crossover is high. Structured pruning gives up sparsity for a tensor that is genuinely smaller, and the multiply–add count falls in proportion. Both columns below are counted, not estimated.

Four ways to decide which weights die
Global magnitude
One threshold over every weight in the network. Layers self-allocate — a fat layer donates more. The risk is layer collapse: a small layer with small weights can be deleted entirely, and the network is then disconnected no matter how much you fine-tune.
Layer-wise magnitude
The same fraction removed inside each layer. Cannot collapse a layer, but ignores that layers differ enormously in redundancy — it over-prunes the fragile first layer and under-prunes the bloated middle.
Random (the control)
Same sparsity, no saliency. Not a method — a measurement instrument. If your clever criterion cannot beat this, it is not doing anything, and a surprising number of published criteria barely do.
Structured (neurons)
Rank whole hidden units by the L2 norm of everything they own and delete the weakest outright. Coarse, so accuracy falls sooner — but the resulting tensor is genuinely smaller and genuinely faster on hardware that exists.
Verification — run in this tab, right now

A pruning implementation is wrong until proven otherwise, and a subtly wrong one still produces a curve that looks plausible — the worst failure mode there is. These checks are exact where exactness is available (mask arithmetic, top-k selection, the structured-equals-compacted identity) and use central finite differences on an untrained network for the gradient. The untrained part matters: at convergence the true gradient has decayed to around 1e−5 while a central difference bottoms out near 1e−11, so a gradient check run at the end of training measures round-off and reports a false failure.

🔨 Build it yourself

    
Pruning is a mask, a sort and a fine-tuning loop — about 120 lines with no dependencies. Below is the exact runnable core the LOOK tab uses: the network, the masked forward and backward pass, the four criteria, the compaction that makes structured pruning real, masked SGD, iterative magnitude pruning, the lottery-ticket rewind, and the accounting that tells you what you actually saved.

    1
    The mask — pruning is elementwise multiplication and nothing else
    
        
    There is no special data structure. A mask is a tensor the same shape as the weights holding 1 for “keep” and 0 for “gone”, and the pruned network is W ⊙ m. Keeping the mask separate from the weights rather than destroying W in place is what lets you compare criteria on the same trained model, un-prune for a sanity check, and — crucially — rewind later without having lost the original values. Every real framework does exactly this: torch.nn.utils.prune stores weight_orig and weight_mask and recomputes weight in a forward pre-hook. The zeros are physically present the entire time; nothing is smaller yet.
    
        
    H, D, C = 32, 144, 3            # hidden, input, classes
W1 = he_init(H, D); W2 = he_init(C, H)
m1 = ones(H, D);    m2 = ones(C, H)          # 1 = keep, 0 = pruned

def forward(x):
    h = relu((W1 * m1) @ x + b1)             # the mask multiplies the WEIGHT
    return softmax((W2 * m2) @ h + b2)

# nnz = the only honest size metric
nnz      = int(m1.sum() + m2.sum())
sparsity = 1 - nnz / (H*D + C*H)
# assert: forward with a mask == forward with those entries hard-zeroed, to 1e-12

    2
    The backward pass, and the one line that makes pruning stick
    
        
    The gradient must be masked too. If you zero a weight and then fine-tune normally, the optimiser sees a perfectly ordinary coordinate with a perfectly ordinary gradient and moves it straight off zero — your 95%-sparse network is dense again after one epoch, silently, with no error message. Multiply the gradient by the same mask and a deleted weight receives exactly 0.0, so it stays at exactly 0.0 forever. Watch momentum too: a stale velocity buffer can push a pruned weight even when its gradient is zero, which is why the update itself is masked here rather than only the gradient. This page asserts that after six epochs of real SGD every pruned coordinate is still bit-for-bit zero while the survivors have all moved.
    
        
    def backward(x, y, cache):
    dlogits = cache.p - onehot(y)                  # softmax + cross-entropy
    gW2 = outer(dlogits, cache.h) * m2             # <-- mask the gradient
    dh  = (W2 * m2).T @ dlogits
    dh[cache.z <= 0] = 0                           # ReLU gate
    gW1 = outer(dh, x) * m1                        # <-- and here
    return gW1, gW2

# and mask the UPDATE as well, or momentum resurrects the dead:
v1 = mom * v1 - lr * gW1;   W1 += v1 * m1
# assert after N epochs: (W1[m1 == 0] == 0).all()   -- exactly, not approximately

    Prove the backward pass — on untrained weights
    
        
    Perturb one weight by ±ε, re-run the forward pass, and compare the slope with what backprop claimed. Use the central difference (error O(ε²), not O(ε)) and a relative tolerance. The trap that costs people a day: run this at the end of training and it fails. At convergence the true gradient has decayed towards 1e−5 while the difference of two nearly identical losses bottoms out around 1e−11 in float64, so the relative error explodes and you go hunting for a bug in code that is correct. Gradient-check a freshly initialised network, where the gradients are large and the check has headroom.
    
        
    eps = 1e-5
for i in sample_coordinates(W1, 24):
    old = W1[i]
    W1[i] = old + eps; Lp = loss(batch)
    W1[i] = old - eps; Lm = loss(batch)
    W1[i] = old
    numeric  = (Lp - Lm) / (2*eps)               # central: O(eps^2)
    analytic = gW1[i]
    rel = abs(numeric - analytic) / (abs(numeric) + abs(analytic))
    assert rel < 1e-6, (numeric, analytic, rel)

# run this on a FRESH net. at convergence it fails for numerical reasons
# and the failure tells you nothing about your code.

    4
    Global magnitude — one sort, one threshold, exact accounting
    
        
    Pool every prunable weight in the network, sort by |w|, keep the top k. Two details separate a correct implementation from an almost-correct one. Break ties deterministically (by flat index) or the mask is not reproducible and neither is anything you conclude from it. And derive k from a single rounding of the total, then assert nnz == k — the most common bug in pruning code is a sparsity that drifts by a few weights per layer until the number you report is not the number you produced. Real implementations use a kthvalue/quickselect at O(N) instead of a full sort; the answer is identical, which makes the full sort a perfect test oracle.
    
        
    def mask_global(W_list, sparsity, prev=None):
    flat = concat([abs(W).ravel() for W in W_list])
    if prev is not None: flat[prev == 0] = -1          # already dead stays dead
    N    = flat.size
    keep = N - round(sparsity * N)                    # ONE rounding, of the total
    order = argsort(-flat, kind="stable")             # ties -> lowest index first
    mask = zeros(N); mask[order[:keep]] = 1
    return unflatten(mask, W_list)

# assert nnz(mask) == keep                       exactly
# assert set(kept) == set(brute_force_top_k)     independent sort agrees
# assert mask(0.9) is a SUBSET of mask(0.8)      pruning harder only removes

    5
    Layer-wise, and the random control you are not allowed to skip
    
        
    Layer-wise pruning removes the same fraction inside every layer. It cannot collapse a layer, which global pruning genuinely can — at extreme sparsity a global threshold will happily delete a small early layer in its entirety and disconnect the network, a failure mode with its own literature under the name layer collapse. It also cannot exploit the fact that layers differ enormously in redundancy. The random mask is not a competing method, it is the instrument that tells you whether your criterion is doing anything: same sparsity, saliency replaced by a coin. Report it on every curve. A criterion that does not beat random has not been shown to work, and several published ones do not by much.
    
        
    def mask_layerwise(W, sparsity):                 # per tensor, same fraction
    k = W.size - round(sparsity * W.size)
    thr = sorted(abs(W).ravel())[-k]
    return (abs(W) >= thr).astype(float)

def mask_random(W, sparsity, rng):               # THE CONTROL
    k = W.size - round(sparsity * W.size)
    idx = rng.permutation(W.size)[:k]
    m = zeros(W.size); m[idx] = 1; return m.reshape(W.shape)

# the only comparison that means anything:
assert acc(magnitude_mask(s)) > acc(random_mask(s))    # at the SAME s

    Structured pruning — and the identity that proves it is real
    
        
    Delete a whole hidden unit and two things vanish together: its incoming row of W₁ and its outgoing column of W₂. Miss the second and you have not removed a neuron, you have removed a feature extractor and left a dangling consumer of zeros. The correctness test is the strongest one on this page and it is exact: build a genuinely smaller network by physically deleting those rows and columns, and its logits must equal the masked network's logits bit for bit. If they do not, your index arithmetic is wrong. Notice the arithmetic falls out too — each hidden unit owns exactly D incoming plus C outgoing weights, so killing k of H units removes exactly k/H of all weights, no rounding involved.
    
        
    score  = [ norm(W1[j, :])**2 + norm(W2[:, j])**2 for j in range(H) ]  # L2 of all it owns
dead   = argsort(score)[: round(sparsity * H)]
m1[dead, :] = 0;  m2[:, dead] = 0            # BOTH sides, or it is not a neuron

# now actually shrink the tensors -- this is the point of structured pruning
keep = [j for j in range(H) if j not in dead]
W1s, b1s, W2s = W1[keep, :], b1[keep], W2[:, keep]

# the exact test:
assert allclose(forward_masked(x), forward_small(W1s, b1s, W2s, x), atol=1e-12)
assert nnz == total - len(dead) * (D + C)    # closed form, no rounding
assert macs == len(keep) * (D + C)           # and the FLOPs really did drop

    Fine-tuning under the mask — the healing step
    
        
    Immediately after a big cut the network is badly damaged; the reported accuracy at that instant is the raw damage, not the result. Fine-tuning lets the survivors redistribute the work the deleted weights were doing, and most of the loss comes back in a handful of epochs. Two practical rules. Use a lower learning rate than the original training run — you are repairing a solution, not searching for one, and a full-size step will knock it out of the basin entirely. And re-check sparsity after fine-tuning: if it moved, your mask is leaking somewhere, usually through momentum or through a weight-decay term applied to the masked-out coordinates.
    
        
    apply_mask_(W, m)                       # hard-zero once, then keep multiplying
for epoch in range(ft_epochs):
    for xb, yb in batches(train, 12):
        g1, g2 = backward(xb, yb)       # already masked
        v1 = mom*v1 - lr_ft*g1;  W1 += v1 * m1
        v2 = mom*v2 - lr_ft*g2;  W2 += v2 * m2

assert (W1[m1 == 0] == 0).all()         # nothing came back
assert nnz_after == nnz_before          # the sparsity you reported is real
# lr_ft is typically 10-50% of the original lr. full-size steps undo the pruning.

    Iterative magnitude pruning — the loop that beats the single cut
    
        
    Prune a slice, heal, prune another slice, heal. Each round the network reorganises around what remains, so the magnitudes you sort on the next round are post-adaptation magnitudes rather than a snapshot of a network that has not yet noticed it lost anything. The schedule is a geometric one: remove p of the survivors per round, so after r rounds the sparsity is exactly 1−(1−p)ⁿ — a closed form worth asserting, because an off-by-one in whether p applies to survivors or to the original total is an easy and completely silent bug. Keep the masks nested: a weight that has been pruned must never come back, which you get for free by scoring dead coordinates as −1. IMP is slow — rounds × ft_epochs of training — and that cost is the entire reason one-shot pruning is still used in production.
    
        
    mask = ones_like(W)
for r in range(1, rounds+1):
    target = 1 - (1 - p)**r                     # geometric, on SURVIVORS
    mask   = mask_global(W, target, prev=mask)  # nested: dead stays dead
    apply_mask_(W, mask)
    finetune(W, mask, epochs=ft_epochs)
    assert nnz(mask) == total - round(target*total)
    assert nnz(mask) < nnz_prev                 # strictly monotone

# 10 rounds at p = 0.25  ->  1 - 0.75**10 = 94.37% sparsity
# compare against ONE cut to 94.37% with the SAME total fine-tuning budget.

    The lottery ticket — and its two controls
    
        
    Save θ₀ before you train anything; without it there is no experiment. After IMP produces a mask, set the surviving weights back to the values they had at initialisation and retrain the sub-network from scratch with the same budget. Frankle & Carbin's claim is that this sparse network trains to full accuracy on its own — that a winning ticket was present in the dense model from step zero. The claim lives or dies on its controls, so run all three: rewound, same mask with a fresh init, and a random mask of the same size. Report per-seed numbers, not just a mean, because on small networks the first two arms are within noise of each other and a single average will let you claim something you did not measure.
    
        
    theta0 = deepcopy(W)                    # BEFORE training. no theta0, no experiment.
W_trained = train(W)
mask      = imp(W_trained, rounds=10, p=0.25)

ticket  = theta0 * mask                      # rewind survivors to their INIT values
control = random_init(new_seed) * mask       # same structure, different values
random_ = random_init(new_seed) * random_mask(same_nnz)

for arm in (ticket, control, random_):
    acc[arm] = train_from_scratch(arm, mask, epochs=SAME_BUDGET)

assert (ticket[mask == 1] == theta0[mask == 1]).all()    # exact rewind
assert acc[ticket] >> acc[random_]                       # never in dispute
# acc[ticket] vs acc[control] is the actual hypothesis -- and it is CLOSE.

    Count what you actually saved — and what ships
    
        
    Sparsity is a property of a tensor, not a property of a runtime. A 95%-sparse weight matrix stored densely takes the same memory and runs the same speed as before; it only becomes a win once you either store it in a sparse format (index overhead is real: CSR costs an index per non-zero, so below roughly 70% sparsity you can end up larger) or run it on a kernel that skips zeros. Structured pruning converts sparsity into a smaller dense tensor, which every runtime already accelerates. The compromise that actually shipped is N:M semi-structured sparsity — NVIDIA Ampere onwards executes a 2:4 pattern (two zeros in every group of four) natively at roughly double the dense rate, which is why 50% structured-ish sparsity is a real production number while 95% unstructured usually is not. Report three numbers, always: non-zeros, multiply–adds, and measured latency on the target device.
    
        
    params_dense = H*D + C*H
nnz          = int(mask.sum())
macs_dense   = H*D + C*H                     # one MAC per weight, batch of 1
macs_pruned  = kept_neurons * (D + C)        # ONLY structured pruning moves this

# unstructured 95% sparse, dense storage: same bytes, same MACs, same latency.
# unstructured 95% sparse, CSR:            ~ nnz*(4+4) bytes + row pointers
# structured  50% neurons removed:         half the MACs, on any runtime, today
# 2:4 semi-structured:                     ~2x on Ampere+ sparse tensor cores

# and always report the one number that is not a proxy:
latency_ms = benchmark(model, device, batch=1)   # <-- this is what users feel
