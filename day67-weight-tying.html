DEEPLEARNINGFROMZERO · DAY 67

🪢 Weight tying — one matrix, two jobs, and a += that is right on 87.5% of its rows. A language model has an input embedding E that turns token ids into vectors and an output projection that turns the final hidden state back into vocabulary logits. Tying makes them the same matrix: logits = h · Eᵀ. It is two lines of code, it is what GPT-2 and most models since do, and almost everything said about it is quoted rather than measured. This page builds a real language model with a hand-written forward and backward pass and measures all of it. The parameter saving is not half — it is 23.7% for GPT-2 small and 0.5% for a character model, and it can never reach half. The gradient into E now arrives by two paths and they must be added; drop one and the gradient is still exactly right on every row you did not look up, which is why the bug survives review and still trains a smooth-looking curve. Tying makes every embedding dense: a token that never appears in the batch still moves, by 2.37e-3 against exactly 0 untied. And because the hidden state carries the input embedding down the residual stream, a freshly initialised tied model's top prediction is "repeat the token you just read" — mean rank 1.7 of 64. Pure vanilla JavaScript, one file, offline.

residual strength is the knob that turned out to matter. The model is h = res·x + W2 tanh(W1 x), so res controls how much of the input embedding survives into the hidden state — and under tying that is exactly how much of E[t] ends up dotted against E[t] in its own logit.

THE REPEAT BIAS TYING CREATES FOR FREE

The training task is built with no fixed points — the true successor of a token is never that token — so any mass on "repeat what you just read" is architecture, not data. Odds is how many times more likely repeating is than the average other token; 1.00 is no bias at all. Rank is where the current token sits in its own logit row, out of V.

THE ASSUMPTION TYING MAKES — AND WHAT IT COSTS WHEN IT IS FALSE

Tying asserts that a token's meaning as an input and its meaning as an output live in the same space. Here that is made true or false on purpose: the next token is scored by dot(z_t, out_v), where out_v is the token's own latent (aligned) or an independent one (misaligned). Both models train from the same seed at the same stable learning rate; the score is excess loss over the task's own entropy, so a ratio of 1.00 means tying is free.

One matrix asked to do two jobs


      
A language model needs two vocabulary-sized matrices. The input embedding
      turns a token id into a vector. The output projection turns the final hidden
      state into one logit per vocabulary entry. Both are [V, d]. Weight tying
      (Press & Wolf 2017, Inan 2016) makes them the same tensor.


      
untied:  x = E[t]          logits = h @ U.T      # two matrices
tied:    x = E[t]          logits = h @ E.T      # one


      
It does not halve the parameters


      
The claim you will read is that tying halves the embedding cost, which is true, and it is
      usually written as if it halves the model. It removes exactly V·d
      parameters, and what fraction of the model that is depends entirely on how
      V·d compares to the 12·L·d² in the blocks.


      
Measured on real configurations: 23.7% for GPT-2 small, 12.7%
      for GPT-2 medium, 4.9% for GPT-2 XL, 45.3% for a
      V=32k, d=128, L=4 toy, and 0.5% for a character-level model with
      a 256-token vocabulary. It can never reach 50%, because reaching 50% would require the model
      to be nothing but embeddings.


      

        
The direction is the opposite of the intuition: tying matters
        least for the big models whose parameter counts you were worried about, and
        most for small models with large vocabularies — which is exactly the regime where
        the embedding table is most of the model and the least data is available to train it.

      


      
The gradient now arrives twice


      
Untied, each matrix has one job and one gradient. Tied, E appears twice in the
      computation graph, so its gradient is a sum over both appearances:


      
output path:  dE[v] += (p[v] - y[v]) * h        for EVERY v   <- dense
input  path:  dE[t] += dx * inScale             for the token <- sparse

dE = output_path + input_path                   # +=, not =


      
Frameworks with autograd do this for you. Hand-rolled implementations, fused kernels and
      any code that builds the embedding gradient with a scatter or an index_add
      routinely get it wrong, and the failure mode is unusually quiet.


      
Why dropping a path survives review


      
Drop the input path and the gradient is not garbage. It is exactly correct on
      every row of E belonging to a token that did not appear in the batch, and wrong
      only on the rows that did. With a batch of 8 distinct tokens over a vocabulary of 64, that is
      87.5% of rows exactly right — and the wrong ones are the rare ones.


      

        
A gradient check that samples random entries passes it. A loss curve
        does not notice it: the broken model still converges smoothly, just to a worse place —
        1.84 against 1.61 on the page's task, on a curve with no kink in it anywhere.

      


      
Tying makes every embedding dense


      
This is the part that is genuinely a training-dynamics change rather than a memory
      saving. Untied, dE is sparse: only the rows you looked up get a gradient, so a
      token absent from the batch does not move at all. Measured here: exactly 0.


      
Tied, the output path touches every row every step, because softmax puts non-zero
      probability on every vocabulary entry and dlogits[v] = p[v] - y[v] is non-zero
      for all v. A token that never appears in the batch still had its embedding
      updated — measured at 2.37e-3 in a single step.


      
That is the real mechanism behind "tying helps small models and rare words". It is not
      regularisation in any formal sense; it is that rare tokens stop being starved of gradient.


      
The repeat bias you get for free


      
A transformer has a residual stream, so the hidden state at the last layer still contains
      a component of the input embedding. Under tying, the logit for token t is
      dot(h, E[t]) — and if h contains E[t], that logit
      contains ||E[t]||², which is the largest self-dot-product in
      the row.


      
Measured on a task with no fixed points, so the correct answer is never the current
      token: at initialisation a tied model ranks the just-read token 1.7th out of
      64, while an untied model ranks it at 31.4 — chance is 32.5. Turn
      the residual strength to zero and the tied model returns to 35.0, which
      identifies the residual stream as the cause rather than tying alone.


      
Training suppresses it but does not remove it. After 600 steps the tied model still ranks
      the current token 20.3rd where the untied model sits at 31.9
      — chance. The bias is outvoted, not deleted, and it is a plausible contributor to the
      repetition that decoder-only models are known for.


      
What tying actually assumes, and what it costs


      
Tying asserts that a token's input representation and its output representation are the
      same vector. That is a real assumption and it can be false — "the" is a useful thing to
      predict and a nearly useless thing to condition on.


      
The page tests it directly with a task whose input and output geometries are either the
      same or independent, held over five seeds:


      
ALIGNED     tied excess 0.2134   untied 0.2143   ratio 1.00x   (32% fewer params)
MISALIGNED  tied excess 0.1657   untied 0.1100   ratio 1.51x


      
When the assumption holds, tying is free — statistically indistinguishable
      at 32% fewer parameters, and the per-seed ratios straddle 1 (0.96 to 1.11). When it does not,
      tying costs 51% more excess loss, and every one of the five seeds agrees
      (1.37 to 1.64). Dropping the residual stream reduces the penalty to 1.30x but does not remove
      it, so the residual accounts for part of the cost and the shared geometry for the rest.


      
One knob, two scales — and a correction


      
Under tying, σE sets the residual-stream scale and the logit
      scale together, but not with the same exponent. |x| is linear in
      σ; the logits are h · E where h itself
      already scales with σ, so the logit scale is roughly quadratic.


      
tied,   sigma x2:  |x| x2.00   logit sd x3.80   <- quadratic
untied, sigma_U x2: |x| x1.00   logit sd x2.00   <- linear, and |x| untouched


      

        
🔴 A claim this page nearly shipped and the measurement
        killed. The first version of this test swept a coarse grid of
        (σ, inScale), found no setting that put both scales near 1, and concluded
        that a tied matrix cannot serve both roles. That was a grid artifact, not a fact.
        A finer sweep finds 19 settings that hit both, clustered at
        σ≈0.68, inScale≈0.4. Two knobs can satisfy two targets. The
        real and much smaller claim is the exponent: tying couples the two scales
        non-linearly, so tuning one perturbs the other quadratically — which is why tied models are
        fussier to initialise, not impossible.

      


      
The short version

  • The gradient into E is a sum of two paths. Dropping one is
        correct on most rows and still trains.
    • 
        
  • Tying makes embedding gradients dense; that, not regularisation, is why
        it helps rare tokens.
    •

    •

🔨 How it is built


      
1. A real model, with a residual stream on purpose

      
x      = E[t] * inScale
h      = res*x + W2 @ tanh(W1 @ x + b1)     // h CARRIES x
logits = h @ Eout.T + bo                    // Eout is E when tied, U when not

      
The residual term is not decoration. Without it, h is an arbitrary function of
      the input and none of the self-logit effect exists — which is why res is a slider
      on the page rather than a constant buried in the code. Setting it to 0 is the control that
      identifies the residual stream as the cause.


      
2. The two gradient paths, kept apart

      
for each v:  gEout[v] += dlogits[v] * h        // DENSE: all V rows, every step
             dh      += dlogits[v] * Eout[v]
...
gEin[t] += dx * inScale                        // SPARSE: one row per token

gE = (mode !== 'input-only'  ? gEout : 0)
   + (mode !== 'output-only' ? gEin  : 0);

      
Accumulating into two separate buffers and combining them at the end is what makes the bug
      reproducible rather than describable. The three modes are the same code path with one
      term switched off.


      
3. The identity that pins the whole mechanism

      
// an UNTIED model whose output matrix starts as a bit-exact copy of E
tied   = initModel({ tied: true });
mirror = initModel({ tied: false, mirror: true });

assert(forward(tied, t).p === forward(mirror, t).p);       // 0.0e+0, identical
assert(grads(tied).gE === grads(mirror).gE + grads(mirror).gU);  // 0.0e+0

      
Two models with an identical forward pass and a different backward pass. The second
      assertion is weight tying, stated as an equation: the tied gradient is exactly the sum
      of the two untied gradients. It holds to 0, not to a tolerance, because it is an algebraic
      identity and not an approximation.


      
4. Gradient checking that does not lie about small entries

      
function gradError(analytic, numeric){
  let scale = 0, worstAbs = 0;
  for (...) { scale = Math.max(scale, |numeric|);
              worstAbs = Math.max(worstAbs, |analytic - numeric|); }
  return { abs: worstAbs, rel: worstAbs / scale };     // relative to the SCALE
}

      
Central differences at eps=1e-5 have an absolute noise floor around 1e-11.
      Dividing that by an entry which is legitimately near zero manufactures a relative error of
      1e-5 and hides real bugs behind a loose tolerance. Comparing against the gradient's overall
      scale reports the honest number: 4.2e-10.


      
5. A task with no fixed points

      
const off = 1 + ((t * 13 + i * 17) % (V - 1));   // off in [1, V-1] => never 0
succ[t][i] = (t + off) % V;                      // so succ[t][i] !== t, ever

      
The offset is constructed to be non-zero rather than filtered afterwards, so the property
      holds by construction and is asserted anyway. Without it, "the model wants to repeat the input"
      is unmeasurable, because repeating would sometimes be right.


      
6. Testing the assumption instead of asserting it

      
// out_v is the token's OWN latent (aligned) or an independent one (misaligned)
const zin = mk(), zout = aligned ? zin : mk();
scores[v] = (v === t) ? -Infinity : beta * dot(zin[t], zout[v]) / sqrt(r);

      
One flag flips whether tying's assumption is true, everything else held fixed, and the
      comparison is excess loss over each task's own entropy — the two tasks have different
      floors (2.33 against 2.47) and comparing raw losses across them would be meaningless.


      
7. Comparing at a learning rate where both are stable

      
lr=0.5   tied 1.653   untied 1.573      // both stable - comparisons live here
lr=2.0   tied 2.082   untied 1.761      // both stable, both worse
lr=8.0   tied DIVERGED untied DIVERGED  // asserted separately, never compared

      
A comparison run at a rate where either side overflows is not a comparison. The instability
      is a separate assertion, and every number quoted on this page comes from the stable regime.


      
8. What the tests pin

      
// the mechanism, as an identity
assert(tied_dE === untied_dE + untied_dU);            // exactly 0

// the bug is wrong on exactly the rows it looked up
assert(wrongRows('output-only') === uniqueTokensInBatch);
assert(wrongRows('input-only')  === V);

// density
assert(nonzeroRows(tied.dE)   === V);
assert(nonzeroRows(untied.dE) === uniqueTokensInBatch);

// the repeat bias is the RESIDUAL, not tying alone
assert(repeatOdds(tied, res=1) > 1.5);
assert(|repeatOdds(tied, res=0) - 1| < 0.25);
assert(|repeatOdds(untied)      - 1| < 0.25);

// and tying can never remove half the parameters
assert(transformerParams(...).saved < 0.5) for every real config;

      
The third block is the one worth stealing. Asserting that the effect disappears
      under the control is what separates a measured mechanism from a coincidence — and it is the
      assertion that would have caught the claim if the residual stream had not been the cause.
