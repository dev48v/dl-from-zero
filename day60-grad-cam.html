DeepLearningFromZero · Day 60

🔥 Grad-CAM — a trained CNN gives you a label and nothing else: it says ring, and you have no idea whether it looked at the ring or at a watermark in the corner. Grad-CAM (Selvaraju et al., 2016) extracts that answer from the network you already have, with no retraining and no architecture change. The idea is three lines of calculus. The last convolutional layer still has coordinates — its feature maps Ak are a small grid, so a value at cell (i,j) still means “there, in the image”; everything after it (global average pooling, the classifier) throws that geometry away. So: run the image forward, pick a class c, and backpropagate its logit yc — not the loss — back to those maps to get ∂yc/∂Ak. Global-average-pool those gradients into one number per channel, αkc = (1/Z)Σij ∂yc/∂Akij — the channel’s importance for that class — then take the weighted sum of the maps and keep only what pushes the score up: Lc = ReLU(Σk αkc Ak). Upsample that little grid, overlay it, and you are looking at the evidence. Below, a real 3-layer CNN with a real backward pass trains live in your browser on shapes it has never memorised, and every heat-map is computed by hand from its own gradients. Ask it for a different class and the heat-map moves to that class’s object; plant a corner watermark in the training set and watch Grad-CAM catch the model cheating; randomise the weights and watch the map turn to noise. 729 parameters, no libraries, 61 assertions verified against finite differences.

Which layer do you tap? Resolution vs semantics

The same image explained at all three convolutions. conv1 is 22×22 — sharp, but each cell only sees a 3×3 patch, so it highlights edges, not objects. conv3 is only 8×8 — blurry, but each cell sees 9×9 pixels and carries class-level meaning. Grad-CAM taps the last conv because that is the best trade the network offers: the deepest features that still have coordinates.

Grad-CAM pools the gradients into one weight per channel. Grad-CAM++ replaces that plain average with a per-pixel weighting αij = g²/(2g² + ΣA·g³) and only counts positive gradients, which spreads the map over several instances instead of the single strongest one. No ReLU shows what the final ReLU is hiding — the blue regions are evidence against the class. The sanity check you must run: randomise the weights

Adebayo et al. (2018) showed that several popular attribution maps barely change when you replace a trained network’s weights with random ones — they were reacting to the image, not to the model, and were therefore useless as explanations. Here the same architecture with untrained weights still produces a plausible-looking blob (edges are edges), but it stops being class-discriminative: the pointing-game score collapses from the number above to roughly a coin flip, because all three classes now get the same map.

Four ways to ask “where did it look?”
CAM (2016)
Weight the last feature maps by the classifier’s own weights: Σk wkcAk. Beautiful — but only legal if the head is exactly global-average-pool → one linear layer. Any fully-connected head, any pooling variant, and you must rebuild and retrain the network.
Grad-CAM (2016)
Replace those weights with pooled gradients αkc. Works on any architecture and any layer, needs no retraining, and on a GAP+linear head it reduces to CAM exactly — a strict generalisation, proved on this page to 1e−15.
Grad-CAM++ (2018)
Same skeleton, different weighting: a per-pixel coefficient from second and third derivatives of exp(yc), and only positive gradients count. Fixes Grad-CAM’s habit of locking on to one instance when the image contains several.
Guided Backprop / saliency
Pixel-resolution and gorgeous — but not class-discriminative: change the target class and the picture barely moves. Guided Backprop also failed the weight-randomisation sanity check. The standard fix is Guided Grad-CAM: multiply the two together.
What to try: (1) In the two-object panel hit new scene a few times and compare the vertical and horizontal heat-maps — same forward pass, same activations, only the backpropagated logit differs, and the blob jumps from one bar to the other. (2) Switch the model to random weights: the map still finds bright edges (the image has not changed) but the three classes now produce nearly the same map, and the pointing score falls to a coin flip. That is why weight randomisation is a mandatory sanity check. (3) Switch the model to trained on a watermark and look at the Clever-Hans panel: it is 97–100% accurate and completely wrong, and the heat-map lands squarely on the corner patch. (4) Move the tap from conv3 to conv1: the map gets sharp and useless — high resolution, no semantics. (5) Flip the method to no ReLU and watch blue regions appear: those are the places that argue against the class, which is exactly what Lc = ReLU(…) throws away. (6) Flip to saliency ∂y/∂x: pixel-perfect, speckled, and it looks the same whichever class you ask for. (7) Drag explain class to a class the model did not predict — Grad-CAM will still show you the best evidence it can find for that answer, which is how you debug a confident mistake.

🔨 Build it yourself

    
Grad-CAM is short — six lines once you have gradients — so the work is in making sure those gradients are right. We will write the network, write the one backward pass Grad-CAM actually needs, check it against central finite differences, then build the map, prove it reduces to CAM exactly, upsample it without the alignment bug everyone ships, and finish with the tests that catch a lying explanation. Every line below is the real code running on the LOOK tab.

    The network: three convolutions, GAP, one linear layer
    
        
    The only structural requirement Grad-CAM has is that some layer still has spatial coordinates. Global average pooling then collapses each map to one number, so the classifier is translation-invariant and the network cannot memorise positions. Note the shapes: the last conv is an 8×8 grid of 8 channels — that grid is the canvas the explanation is painted on.
    
        
    #  24x24x1
#    conv 3x3 s1 -> 22x22x4  ReLU     receptive field 3x3
#    conv 3x3 s2 -> 10x10x6  ReLU     receptive field 5x5
#    conv 3x3 s1 ->   8x8x8  ReLU     receptive field 9x9   <-- A^k, the tap
#    global average pool -> 8 -> dense -> 3 logits -> softmax
def forward(net, x):
    z1 = conv(net.c1, x);  a1 = relu(z1)
    z2 = conv(net.c2, a1); a2 = relu(z2)
    z3 = conv(net.c3, a2); a3 = relu(z3)          # A^k lives here
    g  = a3.mean(axis=(1, 2))                     # global average pool, Z = 8*8
    return net.Wd @ g + net.bd                    # the three logits y^c

    The backward pass Grad-CAM needs is not the training one
    
        
    Training backpropagates the loss and stops at the parameters. Grad-CAM backpropagates a single logit y^c and stops at the activations. So the seed of the backward pass is a one-hot vector on the logits, not p − y, and there is no softmax in the chain at all — using the probability instead of the logit would divide out most of the signal once the model is confident.
    
        
    def tap_grad(net, cache, c, tap):
    """dy^c / dA  for the activations of layer `tap`. Seed = one-hot on logits."""
    Z, K = 8*8, net.C3
    # y^c = SUM_k Wd[c,k] * mean(a3[k])   ->   dy^c/da3[k,i] = Wd[c,k] / Z
    da3 = np.repeat(net.Wd[c] / Z, Z).reshape(K, 8, 8)
    if tap == 2: return da3
    da2 = conv_backward(net.c3, cache.a2, relu_back(cache.z3, da3))
    if tap == 1: return da2
    return conv_backward(net.c2, cache.a1, relu_back(cache.z2, da2))

    Check it before you trust it: central finite differences
    
        
    A hand-written backward pass is wrong until proven otherwise, and a subtly wrong one produces a heat-map that looks plausible — the worst failure mode there is. Perturb one number by ±ε, re-run the forward pass, and compare. Use the central difference (error O(ε²), not O(ε)) and a relative tolerance. This page runs 61 such assertions.
    
        
    def check(f, arr, i, analytic, eps=1e-5):
    old = arr[i]
    arr[i] = old + eps; fp = f()
    arr[i] = old - eps; fm = f()
    arr[i] = old
    numeric = (fp - fm) / (2 * eps)                  # central difference
    rel = abs(analytic - numeric) / max(1e-8, abs(analytic) + abs(numeric))
    assert rel < 1e-5, (analytic, numeric, rel)

# every parameter, against the loss ...
check(lambda: cross_entropy(forward(net, x), t), net.c2.W, 37, dW2[37])
# ... and every feature-map entry Grad-CAM consumes, against the LOGIT
check(lambda: forward_from_tap(net, A, tap)[c], A, 91, tap_grad(...)[91])

  4. 
        
    4
    Grad-CAM itself — pool, weight, ReLU
    
        
    Three operations. Pool the gradient map of each channel into a single importance α; weight the feature maps by it and sum; ReLU so that only the regions pushing the score up survive. The result is an 8×8 map — the same size as the tapped layer, which is the whole point: it is defined in feature-map coordinates, not pixel coordinates.
    
        
    def grad_cam(net, cache, c, tap=2):
    A  = cache.acts[tap]                 # (K, h, w)  the feature maps
    dA = tap_grad(net, cache, c, tap)    # (K, h, w)  dy^c / dA

    alpha = dA.mean(axis=(1, 2))         # (K,)  ONE number per channel
    L     = (alpha[:, None, None] * A).sum(0)
    return np.maximum(L, 0)              # ReLU: keep only positive influence

  5. 
        
    5
    The strongest test: Grad-CAM must equal CAM
    
        
    On a GAP + linear head the algebra is forced. y^c = Σk wkc·(1/Z)ΣijAkij, so ∂y^c/∂Akij = wkc/Z for every cell, and averaging those Z identical numbers gives αkc = wkc/Z. The constant 1/Z is global, so the normalised map is bit-identical to CAM. If your implementation fails this to 1e−10, it is broken.
    
        
    Z = 8 * 8
cam_map = np.maximum((net.Wd[c][:, None, None] * cache.a3).sum(0), 0)   # plain CAM
gc_map  = grad_cam(net, cache, c, tap=2)                                # Grad-CAM

assert np.allclose(grad_cam_alpha(net, cache, c) * Z, net.Wd[c], atol=1e-10)
assert np.allclose(norm01(gc_map), norm01(cam_map), atol=1e-10)
# Grad-CAM is a strict GENERALISATION of CAM, not an approximation of it.

    Upsample it — and don’t stretch corner to corner
    
        
    Nearly every tutorial does cv2.resize(cam, image.shape), which maps map-corner to image-corner. That is wrong: cell j of an 8×8 map with stride 2 and a 9×9 receptive field is the response of a window centred on pixel 2j+4, so the map only covers pixels 4…18 of 24. A corner-to-corner stretch shifts the whole explanation by up to 4 pixels — on a 224×224 input that is a 16-pixel lie.
    
        
    # receptive-field geometry of a stride-1/2 stack, computed once
#   jump  = product of strides          = 2
#   rf    = 1 + SUM (k-1) * jump_before = 9
#   start = centre of cell 0            = (rf - 1) / 2 = 4

def upsample_cam(m, stride, offset, H, W):
    """cell j belongs at pixel j*stride + offset; clamp outside the band."""
    src = (np.arange(H) - offset) / stride
    src = np.clip(src, 0, m.shape[0] - 1)
    return bilinear_sample(m, src, src)          # then overlay with a colormap

    The behavioural test: the pointing game
    
        
    “It looks right” is not a test. Build scenes containing two objects of known classes at known positions, run the forward pass once, and ask for each class in turn: the peak must land on that class’s object. A trained model scores >90% here; the identical architecture with random weights scores about 50%, because its map does not depend on the class at all.
    
        
    hits = 0
for scene in two_object_scenes(30):                 # a bar and a ring, disjoint
    cache = forward(net, scene.image)               # ONE forward pass
    for c, box in enumerate(scene.boxes):
        peak = argmax_pixel(upsample_cam(grad_cam(net, cache, c)))
        hits += dist(peak, box) < dist(peak, scene.boxes[1 - c])

assert hits / 60 > 0.90        # trained
# random weights: ~0.50 — the map stops being class-conditional

    Grad-CAM++ and plain saliency, for contrast
    
        
    Grad-CAM++ keeps the skeleton and changes only how α is formed: a per-pixel coefficient built from higher derivatives of exp(y^c), with negative gradients clipped. Because the exponential factors out of the ratio, the coefficient is a closed form in g = ∂y^c/∂A — no second backward pass needed. Saliency is the other extreme: keep going all the way to the pixels.
    
        
    # Grad-CAM++  (Chattopadhyay et al. 2018), Y = exp(y^c) so e^y cancels
num   = g ** 2
den   = 2 * g ** 2 + (A * g ** 3).sum(axis=(1, 2), keepdims=True)
a_ij  = np.where(den != 0, num / den, 0)
alpha = (a_ij * np.maximum(g, 0)).sum(axis=(1, 2))     # positive gradients only

# plain saliency: same backward pass, one layer further
saliency = np.abs(conv_backward(net.c1, x, relu_back(z1, tap_grad(..., tap=0))))

    In PyTorch: two hooks and you are done
    
        
    On a real backbone you do not reimplement anything — you hook the layer you want, run one forward and one backward from the chosen logit, and apply the same three lines. Remember to zero the gradients, to backprop the logit not the loss, and to run the sanity checks: randomise the weights and confirm the map dies.
    
        
    feats, grads = {}, {}
layer = model.layer4[-1]                                  # last conv block
layer.register_forward_hook (lambda m,i,o: feats.update(a=o))
layer.register_full_backward_hook(lambda m,gi,go: grads.update(g=go[0]))

logits = model(x)                       # x: (1,3,224,224)
model.zero_grad()
logits[0, c].backward()                 # the LOGIT for class c, not the loss

alpha = grads['g'].mean(dim=(2, 3), keepdim=True)         # (1,K,1,1)
cam   = torch.relu((alpha * feats['a']).sum(1))           # (1,7,7)
cam   = F.interpolate(cam[None], size=x.shape[-2:], mode='bilinear',
                      align_corners=False)[0, 0]
cam   = (cam - cam.min()) / (cam.max() - cam.min() + 1e-8)

🎉 Day 60 of DeepLearningFromZero done.
Grad-CAM turns a classifier into its own explainer with three operations and no retraining. Tap the last convolutional layer — the deepest place where activations still have coordinates — backpropagate the logit of the class you are asking about to get ∂yc/∂Ak, global-average-pool those gradients into one importance αkc per channel, and take Lc = ReLU(Σk αkcAk). The ReLU is not decoration: without it the map mixes evidence for and against the class. On a global-average-pool + linear head the pooled gradient is provably wkc/Z, so Grad-CAM reduces exactly to CAM — verified here to 1e−15 — while still working on architectures CAM cannot touch. Because it is conditioned on a class, the map moves when you ask about a different one, which is what plain saliency and Guided Backprop cannot do; and because it is conditioned on the model, it exposes shortcuts — the poisoned model on this page is ~100% accurate and looks straight at the watermark. Always upsample with the receptive-field geometry rather than a corner-to-corner stretch, always run the weight-randomisation sanity check, and remember that an explanation is a hypothesis about the model, not proof about the world. 👉 Tomorrow, Day 61: Capsule Networks — keep the pose and part-whole structure a CNN throws away.
