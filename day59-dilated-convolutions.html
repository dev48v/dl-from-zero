DeepLearningFromZero · Day 59

🔲 Dilated (Atrous) Convolutions — every output of a CNN only ever sees a small window of the input called its receptive field, and stacking plain 3×3 layers grows that window only linearly: RF = 2L + 1, so 10 layers still see just 21 samples — nowhere near enough context to segment an object or model a second of audio. The classic escape was pooling / striding, but that buys context by throwing away resolution, which is fatal for dense per-pixel tasks. Dilated convolution (also called à trous, “with holes”) fixes it with one idea: leave gaps between the kernel taps. A 3-tap kernel at dilation d reads x[i], x[i+d], x[i+2d] instead of three neighbours — its effective size becomes d(k−1)+1 while its parameter count and FLOPs stay exactly the same. Stack layers with doubling rates 1, 2, 4, 8… and the receptive field explodes exponentially — RF = 2L+1 − 1, so those same 10 layers now see 2047 samples, at full resolution, for identical cost. That single trick powers WaveNet, DeepLab/ASPP and modern TCNs. Below: run a real dilated convolution over a real signal and a real grid, watch the kernel’s sampling pattern spread out, trace the actual dependency cone from one output back to every input it touches, compare exponential vs linear receptive-field growth — and see the gridding artifact that appears when you get the rates wrong. Dilation is choosing a scale.

Real dilated convolution over a real signal — dilation picks the scale the filter responds to

The input (grey) is a slow swell with a wide plateau and a fast ripple of period 4 riding on top. A [1,0,−1] kernel differences samples 2d apart, so its gain on a wave of frequency ω is 2|sin(ωd)|. At d=1 the ripple sits at maximum gain and drowns everything out. Push d to any even number and the taps land on the same ripple phase, so it cancels to exactly zero — the identical three weights now see only the slow swell and the plateau edges. Dilation is not “more context”; it is choosing which scale to look at.

Receptive field vs depth — exponential vs linear (log scale)

Three ways to give a CNN more context
Stack more plain layers
RF grows as 2L+1 — linear. To see 2047 samples you need 1023 layers. Full resolution, but the depth (and the parameters, and the compute) are absurd.
Pool / stride down
RF grows fast because every unit is worth more input — but you throw away resolution. For segmentation or audio you then need clumsy upsampling / deconv to get the detail back.
Dilate the kernel
RF grows as 2L+1−1 — exponential — at identical parameters, identical FLOPs and full resolution. The one caveat: choose the rates so they don’t leave holes.
The catch: the gridding artifact

If every layer uses the same rate, the tap positions all land on the same lattice, so the stack’s receptive field is full of holes — the output is wide but blind to most of what it spans, and neighbouring outputs see disjoint sample sets (checkerboard artifacts). Switch the preset above to 4,4,4,4 and watch the peach cells appear; switch to 1,2,5 (Hybrid Dilated Convolution) and the coverage becomes solid again.

Set d=8 and the slow swell peaks. Same three numbers, three different feature detectors, zero extra cost.

🔨 Build it yourself

    
Dilated convolution is a one-character change to the indexing of an ordinary convolution — so we’ll write the ordinary one first, add the stride inside the kernel, prove it equals a zero-stuffed plain kernel, extend it to 2-D, derive the receptive field of a whole stack, verify that formula by actually running the layers, and finish with the gridding trap and a WaveNet-style block. Every line by hand.

    An ordinary 1-D convolution
    
        
    Slide a k-tap kernel along the signal; each output is a dot product of the kernel with k consecutive samples. Note the two things we will change: the tap offsets j, and nothing else.
    
        
    import numpy as np

def conv1d(x, w):
    k = len(w)
    return np.array([
        sum(w[j] * x[i + j] for j in range(k))    # taps at i, i+1, ..., i+k-1
        for i in range(len(x) - k + 1)            # 'valid' mode, stride 1
    ])

    Add the dilation: j becomes j*d
    
        
    That is the entire algorithm. The kernel now reads x[i], x[i+d], x[i+2d]… The effective kernel size is d(k-1)+1, but the number of weights — and the number of multiplies — is still k.
    
        
    def conv1d(x, w, d=1):
    k    = len(w)
    eff  = d * (k - 1) + 1                 # span covered by the kernel
    return np.array([
        sum(w[j] * x[i + j*d] for j in range(k)),   # <-- j*d, the whole trick
    ] for i in range(len(x) - eff + 1))

# d = 1 -> the ordinary convolution.  d = 4, k = 3 -> spans 9 samples, 3 weights.

    Prove it: dilation == a kernel stuffed with zeros
    
        
    “À trous” means “with holes”. Insert d-1 zeros between every pair of taps and run a plain convolution — you get bit-identical output. That equivalence is why dilation needs no new math, and why a framework can implement it as pure indexing (the zeros are never actually multiplied).
    
        
    def dilate_kernel(w, d):
    out = []
    for j, v in enumerate(w):
        out.append(v)
        if j < len(w) - 1:
            out.extend([0.0] * (d - 1))        # the "holes"
    return np.array(out)

assert np.allclose(conv1d(x, w, d=4),
                   conv1d(x, dilate_kernel(w, 4), d=1))   # identical
# ...but the dilated version never multiplies by those zeros -> same FLOPs as d=1

    2-D: the atrous filter (DeepLab)
    
        
    Exactly the same edit on both axes. A 3×3 kernel at d=6 covers a 13×13 footprint with nine weights — that is how DeepLab gets a huge field of view for semantic segmentation while keeping the output map at the input resolution.
    
        
    def conv2d(X, K, d=1):
    kh, kw = K.shape
    eh, ew = d*(kh-1)+1, d*(kw-1)+1
    H,  W  = X.shape
    out = np.zeros((H-eh+1, W-ew+1))
    for r in range(out.shape[0]):
        for c in range(out.shape[1]):
            out[r, c] = sum(K[a, b] * X[r + a*d, c + b*d]
                            for a in range(kh) for b in range(kw))
    return out

    The receptive field of a stack
    
        
    Each stride-1 layer widens the window by (k-1)*d, and the widenings simply add up. Doubling the rates turns that sum into a geometric series, which is where the exponent comes from.
    
        
    def receptive_field(ks, ds):
    return 1 + sum((k - 1) * d for k, d in zip(ks, ds))

L  = 4
rf_dilated = receptive_field([3]*L, [2**i for i in range(L)])   # 1 + 2*(1+2+4+8)
rf_plain   = receptive_field([3]*L, [1]*L)                      # 1 + 2*4
print(rf_dilated, rf_plain)          # 31   9
# closed forms:  dilated = 2**(L+1) - 1        plain = 2L + 1

    Verify the formula by actually running the layers
    
        
    Don’t trust the algebra — measure it. With ‘valid’ stride-1 layers the output shrinks by exactly RF-1, so RF = len(x) - len(y) + 1. Better still, poke one input and see which outputs move: that is the receptive field, empirically.
    
        
    def run_stack(x, ks, ds):
    for k, d in zip(ks, ds):
        x = conv1d(x, np.ones(k), d)
    return x

N  = 400
rf_measured = N - len(run_stack(np.random.randn(N), [3]*4, [1,2,4,8])) + 1
assert rf_measured == receptive_field([3]*4, [1,2,4,8]) == 31

# perturbation test: which inputs move output q?
def support(N, ks, ds, q):
    base = run_stack(np.zeros(N), ks, ds)[q]
    return [p for p in range(N)
            if run_stack(np.eye(N)[p], ks, ds)[q] != base]

    The gridding trap — and how to detect it
    
        
    A wide receptive field is worthless if most of it is holes. The set of inputs one output touches is the Minkowski sum of each layer’s tap offsets; if its size is smaller than RF, you have gridding. Rates that share a common factor are the usual culprit — use co-prime / sawtooth schedules (HDC) instead.
    
        
    def reachable(ks, ds):
    S = {0}
    for k, d in zip(ks, ds):
        S = {p + t*d for p in S for t in range(k)}    # Minkowski sum
    return S

for ds in ([1,2,4], [4,4,4], [2,4,8], [1,2,5]):
    rf, cov = receptive_field([3]*3, ds), len(reachable([3]*3, ds))
    print(ds, f"RF={rf:3d}  touched={cov:3d}  {'OK' if cov == rf else 'GRIDDING'}")
# [1,2,4] RF= 15 touched= 15 OK      [4,4,4] RF= 25 touched=  7 GRIDDING
# [2,4,8] RF= 29 touched= 15 GRIDDING [1,2,5] RF= 17 touched= 17 OK

    Put it in a real block (WaveNet / TCN / ASPP)
    
        
    In practice dilation is wrapped in a residual block and the rate cycles 1,2,4,…,512 then restarts — each cycle adds field without the rate running away. Padding keeps the length fixed (causal padding on the left for audio); in vision, several rates run in parallel and are concatenated: that is ASPP.
    
        
    import torch.nn as nn

# 1-D: a TCN / WaveNet residual block — note dilation= is just an argument
class DilatedBlock(nn.Module):
    def __init__(self, ch, d, k=3):
        super().__init__()
        self.conv = nn.Conv1d(ch, ch, k, dilation=d, padding=d*(k-1)//2)
        self.act  = nn.ReLU()
    def forward(self, x):
        return x + self.act(self.conv(x))          # residual keeps it trainable

net = nn.Sequential(*[DilatedBlock(64, 2**i) for i in range(10)])   # RF = 2047

# 2-D: ASPP — the SAME features seen at four scales, in parallel, then fused
aspp = [nn.Conv2d(c, c, 3, dilation=r, padding=r) for r in (1, 6, 12, 18)]

🎉 Day 59 of DeepLearningFromZero done.
Dilated (atrous) convolution changes one index — x[i+j] becomes x[i+j·d] — so the kernel’s taps sit d apart instead of adjacent. Its effective size jumps to d(k−1)+1 while its parameters and FLOPs do not move at all, and it is provably identical to convolving with a kernel stuffed with d−1 zeros (the “holes”). Because a stride-1 stack has RF = 1 + Σ(k−1)di, giving each layer double the previous rate turns that sum into a geometric series: RF = 2L+1−1 — exponential growth, where plain stacking gives only 2L+1. Ten layers see 2047 samples instead of 21, at the same cost and the same resolution, which is why WaveNet can model raw audio, DeepLab/ASPP can segment pixel-perfect masks without downsampling, and TCNs can replace RNNs on long sequences. The one trap is gridding: if the rates share a common factor the receptive field is wide but full of holes — the fix is co-prime / sawtooth schedules like 1,2,5.
