DLFROMZERO · DAY 83

Prefix Tuning (Soft Prompts) — LoRA edits a weight matrix; prefix tuning edits nothing, and steers a frozen model entirely from P extra key/value rows the attention softmax is forced to look at.

Two methods, one sentence apart

This series already built LoRA, so the useful thing is not another tour of parameter-efficient tuning — it is the exact line where the two methods stop agreeing. LoRA computes Weff = W + BA: it changes a weight matrix by a low-rank delta, and at inference you can add the delta in and forget it ever existed. Prefix tuning never forms a delta. It leaves every weight bit-for-bit where it was and prepends P learned key rows and P learned value rows to the attention of every layer.

Where the gradient actually stops

Both methods are trained by ordinary backpropagation through the frozen network, so the gradient travels the same road. What differs is where it gets to stop. In LoRA it stops in A and B, which sit inside a weight matrix's product. In prefix tuning it stops in the first P rows of the concatenated K and V — rows that were never produced by a weight matrix at all, so there is no matrix for the gradient to accumulate into. 


    

      Those two concat lines are the entire mechanism. Everything
      else on this page is consequences.
    

  


  

    
What that buys you, in numbers

    

      A prefix costs 2 × L × P × d numbers:
      one key row and one value row, of width d, per slot, per
      layer. Notice what is not in that formula — the vocabulary,
      and the feed-forward width, which is where most of a transformer's
      parameters actually live. So the ratio improves as the model gets fatter.
    

    

    

  


  

    
Why a soft prompt is not a prompt

    

      People reach for the phrase "learned prompt", and it misleads twice. A
      real prompt is a sequence of token ids, so it is confined to the
      embedding points the vocabulary happens to contain, and it enters only at
      layer 0 — every later layer sees it second-hand, through whatever
      the layers below made of it. A prefix is a free vector, anywhere in
      Rd, and it is injected separately into every
      layer, with a different learned value each time.
    

    

    

  






  

    
Building it, one idea at a time

    

      Twelve steps, each one concept. Everything below runs in this page —
      no framework, no autodiff, no imports. The model is deliberately tiny
      () so every number is checkable by hand.
    

  

  

    

      
STEP 1 OF 12

      
The frozen base, built once and never written to again

    

    

      Start with the thing you are not allowed to change. This is an embedding
      table, two single-head attention blocks with a residual, mean pooling and
      a classifier head — a transformer with all the fat trimmed off but
      none of the shape changed. Every number in it comes from a seeded
      Gaussian, so the page is the same page on every reload. In real prefix
      tuning this object is a pretrained model that cost someone a datacentre;
      here it is a few hundred random numbers, which is enough to make the
      point. The only property that matters is that from this line onward,
      nothing writes to it.
    

    

    

      We go further than politeness: the base is handed to
      Object.freeze, recursively, before training starts. If any
      line of the optimiser reached for a weight, it would be reaching for a
      frozen array.
    

  


  

    

      
STEP 2 OF 12

      
Attention has exactly two places you can inject without touching a weight

    

    

      Inside a block, a token's vector x becomes three things:
      a query q = x Wq, a key
      k = x Wk and a value
      v = x Wv. The query asks a question, the keys
      answer it with a score, the softmax turns those scores into a mixture,
      and the values are what actually gets mixed. If you want to change the
      answer without changing any W, you have two options: add new
      keys, so there is something new to score against, and add new values, so
      there is something new to mix in. You cannot add a new query —
      queries are per-token, and you are not adding tokens. That asymmetry is
      why the method is called key/value prefixing and not "prompt tuning".
    

    

  


  

    

      
STEP 3 OF 12

      
The prefix: the only trainable object on this page

    

    

      It is two three-dimensional tables, K[L][P][d] and
      V[L][P][d]. Read that as: for each of the L
      layers, P slots, each slot a vector of width d.
      They are not embeddings of anything, they are not tied to a vocabulary
      entry, and nothing produced them — they are free coordinates,
      initialised small so that at step zero the prefix barely perturbs the
      model. P = 0 is a legal value and must give the original
      model back exactly, which is a claim the self-check tests rather than
      asserts. Everything the training loop learns, it learns into these two
      tables.
    

    

  


  

    

      
STEP 4 OF 12

      
The forward pass, with two concat lines doing all the work

    

    

      Compute q, k and v exactly as
      before, then stick the prefix rows on the front of K and
      V. Every query now scores against P + T
      candidates instead of T, and the softmax — which must
      sum to one — has no choice but to spend some of its mass on them.
      That is the leverage: the prefix does not add a term to the output, it
      takes mass away from the real tokens and redirects it to vectors
      you control. Notice what the function does not contain: no addition to
      any W, no low-rank product, no second copy of a weight
      matrix. The output is still T rows of width d,
      whatever P is, which is why you can bolt this onto a
      pretrained stack without touching a single downstream shape.
    

    

  


  

    

      
STEP 5 OF 12

      
Every layer gets its own prefix, and that is the point

    

    

      A text prompt enters once, at the bottom, and every layer above sees only
      what the layers below did to it. A prefix is injected independently into
      layer 0, layer 1, and so on up — with different learned vectors
      each time. So the method can say one thing to the layer that handles
      surface syntax and a different thing to the layer that handles the task,
      which no sequence of tokens at the input can do. This is also why the
      parameter count carries a factor of L: you are not learning
      a prompt, you are learning L of them.
    

    

  


  

    

      
STEP 6 OF 12

      
A task the frozen model cannot already do

    

    

      The demonstration is worthless if the base model solves the task by
      accident, so the task is built to be invisible to it: each sequence is
      filler tokens with exactly one signal token hidden at a seeded position,
      and the label is which signal it was. The frozen base has never seen this
      convention and sits at chance. Mean-pooled logits go through a softmax
      cross-entropy, which is the standard "how surprised were you by the right
      answer" loss. If the loss moves, the prefix moved it — there is
      nothing else in the system that can.
    

    

  


  

    

      
STEP 7 OF 12

      
Backprop, written out: down to the attention weights

    

    

      No autodiff here, so the chain rule is spelled out in the order it is
      walked. The gradient of a softmax cross-entropy at the logits is the
      famous p − onehot(y). Mean pooling divides it evenly
      across the T output rows. The residual
      y = x + cWo splits the incoming gradient in two:
      one copy continues straight down the skip connection, the other goes
      through Wo into the attention output
      c. From c = Σj aj
      Vj you get both pieces at once: the value rows each
      receive aj of the gradient, and the attention
      weights each receive the dot product of the gradient with their value.
    

    

  


  

    

      
STEP 8 OF 12

      
The split — where the gradient stops, and where it carries on

    

    

      This is the step that distinguishes prefix tuning from every method that
      edits weights. After the softmax derivative, you hold a gradient for all
      P + T key rows and all P + T value rows. The
      first P of each were not computed from anything —
      they are the parameters, so their gradient is the answer and the chain
      ends there. The remaining T were produced by
      Wk and Wv from the token
      vectors, so their gradient must keep travelling, back through those
      matrices and into x, and on down to the layer below —
      because layer 0's prefix is only reachable through layer 1's attention.
      The gradients dWq, dWk, dWv,
      dWo are never formed. Not computed and discarded, not
      zeroed after the fact: the lines that would build them are absent.
    

    

  


  

    

      
STEP 9 OF 12

      
The update: SGD with momentum, over a parameter list of two tables

    

    

      A training step is now almost boring, which is the compliment it deserves.
      Average the gradient over the batch, keep a velocity buffer so the
      updates do not zig-zag, and step. Read the inner loop and note what it is
      indexing: prefix.K and prefix.V, and nothing
      else. The optimiser has no entry for an embedding table, no entry for a
      projection, no entry for the classifier head. We fingerprint all of the
      base model's numbers before the loop and again afterwards, and the two
      fingerprints are compared in the self-check — a run that moved a
      single weight would change the hash.
    

    

  


  

    

      
STEP 10 OF 12

      
Proving the hand-derived gradient is the real one

    

    

      A derivation written by hand is a hypothesis until something independent
      agrees with it. So: pick one number in the prefix, nudge it up by
      h, measure the loss, nudge it down by h, measure
      again, and divide the difference by 2h. That central finite
      difference knows nothing about softmax derivatives or residual splits
      — it only knows how to call the forward pass twice. The self-check
      runs it over every coordinate of a small prefix and compares against the
      analytic value; the worst relative disagreement is reported on this page,
      and it is at the level of floating-point noise.
    

    

  


  

    

      
STEP 11 OF 12

      
The control: P = 0 has to be the untouched model

    

    

      Here is the sharpest way to state what prefix tuning does to a model,
      which is nothing. We write the forward pass a second time with the prefix
      machinery textually absent — no concatenation, no P,
      no prefix argument — and require that the prefix-aware version with
      P = 0 returns bit-identical logits. Not close, identical,
      compared with Object.is. If that ever fails, the prefix path
      is perturbing the base model even when it is switched off, and every
      other claim on the page is worth less.
    

    

  


  

    

      
STEP 12 OF 12

      
The reparameterisation trick: generate the prefix, do not store it

    

    

      The original paper found direct optimisation of the table unstable and
      generated it instead: a small embedding E per slot, through
      an MLP, out to all 2 × L × d numbers that slot
      needs. Two things change. The output layer is bounded, so no step
      however large can send a prefix coordinate to infinity. And the MLP is
      shared across all slots and all layers, so a gradient step moves
      the whole prefix coherently rather than letting hundreds of coordinates
      wander off independently. After training you run the MLP once, keep the
      2LPd numbers it produced, and throw the generator away
      — so the thing you ship is identical either way. The Demo tab
      measures what the bound is worth, and what it costs.
