DEEPLEARNINGFROMZERO · DAY 68

🎓 Teacher forcing — training on histories the model will never see, and a cure whose fixed point is not the truth. Every sequence model is trained with the ground-truth previous token as its input and then asked to generate with its own previous token. That mismatch has a name, exposure bias, and almost everything said about it is quoted rather than measured. This page builds a data process that is a finite-state machine, so the true next-token distribution is computable after any history — including one the model invented — and every number below is an exact dynamic program, not a sample. A model that can represent the process has a gap of 3.1e-33; a model that cannot is 1.85× worse on its own prefixes than on the data's. The gap does not compound: it is exactly 0 for two steps, reaches 90% of its final size by step 13, and then stops. Scheduled sampling's fixed point is derived in closed form and confirmed to 5.6e-17 — it is an ε-blend of the truth with a distribution that has forgotten the context. And the diagnostic everyone reports predicts whether the cure helps at AUC 0.529, which is a coin flip. Pure vanilla JavaScript, one file, offline.

The process is a latch language: a hidden mode decides which tokens are likely, and a token is a switch token if it resets the mode. switch rate is the probability of emitting one, so 1/switchRate is how many steps the process remembers — it turned out to be the knob that decides everything on this page, so it is a slider rather than a constant. mode separation is how much the hidden state matters: at 0 the modes emit identically and the latent state is decoration. The tabular model of order k sees only the last k tokens, so it cannot see the mode unless a switch token is still inside its window — that is the entire source of its error.

Two loops that are not the same loop


      
Every autoregressive model is trained like this:


      
train:     input[t] = y[t-1]        <- the GROUND TRUTH previous token
generate:  input[t] = yhat[t-1]     <- the model's OWN previous token


      
Feeding the true token during training is called teacher forcing. It is
      not a trick or an approximation: it is exactly maximum likelihood on the factorisation
      p(y) = ∏t p(yt | y<t), every step is
      independent so the whole sequence trains in parallel, and it is why transformers train at all.
      The objection is that the model is only ever shown prefixes drawn from the data, and
      at generation time it must condition on prefixes drawn from itself. That mismatch is called
      exposure bias (Ranzato 2015; the term goes back to Bengio's scheduled
      sampling, 2015).


      
Making it a number instead of an argument


      
The reason this is usually argued rather than measured is that "how wrong is the model on
      its own generations" needs a ground truth for sequences that were never in the data. Here the
      data process is a finite-state machine, so the true next-token distribution
      after any token history is available — including a history the model
      hallucinated. Both numbers are then the same functional:


      
excess = E[ KL( p_true(. | prefix) || p_model(. | prefix) ) ]

teacher-forced :  prefix ~ the DATA
free-running   :  prefix ~ the MODEL   (and p_true conditions on what the model ACTUALLY said)


      
Both are computed by propagating the joint distribution over (true hidden state, model
      context) forward — a dynamic program, not a Monte-Carlo estimate. The two runs share a
      loss function, a parameter vector and a start state, and differ in one line.


      
Exposure bias is model error wearing a different hat


      

        
On a first-order Markov chain, where a tabular order-1 model can
        represent the process exactly, the measured gap is 3.1e-33. Teacher forcing
        is unchanged. What changed is that there is no error to expose.

      


      
Swap in a process with a hidden mode that the model cannot see, and the same code reports a
      teacher-forced excess of 0.107 nats and a free-running excess of
      0.199 — 1.85× worse on its own prefixes.


      
The mechanism is not that errors "accumulate". It is that a model's own output carries
      less information about the hidden state than real data does. Real data emits a token
      from one particular mode; the model, uncertain about the mode, emits from a blend. Its own
      history is therefore a weaker cue than the history it was trained on — and it has to
      condition on it anyway.


      
It does not compound


      
Measured per step, the gap is exactly 0 at steps 1 and 2 — both loops
      start from the same state, and after MLE the model's first-token distribution is exactly right,
      so the two prefix distributions at step 2 are identical, not merely similar. Then it opens, and
      then it stops:


      
step    1     2       3        4      ...     12       40       120
gap     0     0    0.0854   0.1287   ...   0.1912   0.2117   0.2128   <- asymptote 0.21279


      
90% of the final gap is present by step 13, and the increment from step 119
      to step 120 is 2.7e-8. Both prefix distributions are ergodic and converge to
      their own stationary distributions; the gap is the fixed difference between two stationary
      averages. Across switch rates the saturation step tracks the process's own memory
      1/switchRate at about 1.4–2.5×, which is the mechanism stated as a
      prediction.


      

        
"Errors compound over long sequences" is the argument for why exposure
        bias should get worse the longer you generate. In an ergodic process it cannot: the gap is
        fully developed inside about one and a half memory-lengths and flat for the next hundred
        tokens.

      


      
A single wrong token has a lifetime, and it is the model's


      
Force one token the model did not see into its context and the disturbance dies in
      exactly k steps for a model of order k — not approximately, to
      1e-17. The step it lands on costs 3.02× the usual excess at
      k=1; nothing after it costs anything at all.


      
The counterintuitive part is the direction: a larger context makes a single mistake
      both more expensive and longer-lived (8.4×, 6.9×, 5.4× over
      three steps at k=3). A recurrent net has no cut-off, so it decays instead
      — measured at about 0.70 per step for a two-unit RNN. Either way the
      mistake is forgotten, and the forgetting rate is a property of the model, not of the
      training loop.


      
Scheduled sampling, and what it actually converges to


      
The standard fix (Bengio et al. 2015) replaces the input token with the model's own sample
      with probability ε. For sequences of length 2 the fixed point of that
      procedure can be written down by hand. The sampled first token is drawn from the model's own
      marginal and is independent of the true first token, so context c is
      reached carrying the true conditional with weight (1-ε)p0(c) and
      the context-free marginal with weight ε p0(c):


      
q_ss(. | c) = (1 - eps) * P(. | c) + eps * m,      m[v] = sum_y p0(y) P(v | y)


      
Run the procedure to convergence and the measured fixed point matches that expression to
      5.6e-17. So scheduled sampling does not fit the truth. It fits an
      ε-blend of the truth with a distribution that has forgotten the context
      entirely, and the resulting KL from the truth grows as roughly
      ε1.9 — second order, which is exactly why a small
      ε looks free. This is Huszár's 2015 objection, made into a number.


      

        
🔴 The applied gradient is not the gradient of the objective being
        evaluated. At ε=0 the two agree to 1.6e-10, because
        under teacher forcing the rollout genuinely does not depend on the parameters. At
        ε=1 the worst entry is off by 9.7%, though the cosine
        is still 0.9929 — it is mostly the right direction, which is why nobody notices. And at
        the fixed point the procedure converges to (at ε=0.5), the applied gradient
        is 4.7e-17 while the true gradient of the expected loss is
        3.0e-3: one step along it lowers the loss the procedure claims to be
        minimising. The fixed point is not a minimum of anything it computes.

      


      
And yet it sometimes works


      
A first pass of this page swept three values of ε on one process, found
      that scheduled sampling lost every time, and was going to say so. A fine sweep says otherwise:
      across 90 processes and a 0.05 grid, scheduled sampling's best ε
      beat teacher forcing on free-running excess in 28 of them, by up to
      31.1%. It also lost by up to 376%. Its bias is real and its
      benefit is real, and which one you get is not a matter of opinion — it is measurable in
      advance.


      
What predicts it, measured as the AUC of ranking winners above losers:


      
the exposure gap RATIO   (free / teacher-forced)   AUC 0.529    <- a coin flip
the absolute gap                                  AUC 0.855
the plain teacher-forced excess                   AUC 0.956    <- how bad the model is
1 / switchRate  (how long the process remembers)  AUC 0.770


      

        
🔴 The exposure gap is the number reported to justify doing something
        about exposure bias, and it carries no information about whether doing
        something will help: 0.529 against a chance value of 0.5, with winners averaging 3.33 and
        losers 3.52. The quantity that does answer the question is how bad the model is under plain
        teacher forcing — AUC 0.956.

      


      
Closing the gap is not the goal


      
On the page's default process the whole trade is visible in one table.
      ε from 0 to 1 raises the teacher-forced excess from 0.107
      to 0.199 (85% worse) and drives the gap from 0.0912 to
      0.0024 (essentially closed). Free-running excess, the thing anyone actually
      cares about, is U-shaped: best at ε=0.60 at 0.1897, and
      at ε=1, where the gap is smallest, it is 0.2009 —
      worse than not trying at all.


      
Across 36 processes, the ε that minimises the gap was the
      ε that minimises free-running excess in 0 of them; it was
      ε=1 in all 36. And selecting ε by held-out
      teacher-forced loss — the validation number you actually have — picks
      ε=0 every time, because that loss is monotone in ε.
      The standard procedure cannot tune the standard fix.


      
The short version


      
    
        
  • Exposure bias is model error under a different prefix distribution. A
        model that can represent the process has a gap of 3.1e-33.
    • 
        
  • The gap does not compound: 0 for two steps, 90% developed by step 13,
        flat for the next hundred.
    • 
        
  • One wrong token lasts exactly as long as the model's memory of it and
        costs nothing afterwards.
    •

    •

🔨 How it is built


      
1. A process whose truth survives being lied to

      
process = { V, S, start, emit[S][V], step(s, y) }
p_true(. | history) = emit[ fold(step, start, history) ]

      
This is the whole reason the page can exist. Scoring a model on its own generations needs
      the right answer for sequences that never occurred, and a finite-state process supplies it for
      any token string at all. Everything else — every expectation, every gap, every fixed
      point — is a dynamic program over the joint (true state, model context) and carries no
      sampling noise.


      
2. One rollout function, three drivers

      
'data'  : y ~ emit[s];   s' = step(s,y);  ctx' = push(ctx, y)      // teacher forcing
'model' : y ~ q[ctx];    s' = step(s,y);  ctx' = push(ctx, y)      // free running
'ss'    : y ~ emit[s];   s' = step(s,y);                           // scheduled sampling
          ctx' = push(ctx,  rand < eps ? sample(q[ctx]) : y )

      
Under 'model' the true state also follows the model's tokens. That is
      not a detail: "the right answer" for a generated prefix is the right answer given what the
      model actually said, and scoring against the answer for a sequence it did not produce would
      measure something else entirely.


      
3. Teacher-forced MLE has a closed form, so it is not fitted

      
// under the 'data' driver the context distribution does not depend on q at all
q(. | c) = ctxTarget[c] / ctxWeight[c]                   // one pass, exact

      
No learning rate, no step count, no seed, nothing to tune away a result with. Scheduled
      sampling gets no such luxury — its contexts are produced by the model being trained
      — so it is iterated to a fixed point and the iteration count and residual are both
      reported (typically 11–17 iterations to 1e-15).


      
4. The closed form that is checked, not asserted

      
ssClosedFormT2:  q_ss(.|c) = (1-eps) * P(.|c) + eps * m
measured fixed point vs that expression:  5.6e-17

      
Derived on paper from the fact that the sampled first token is independent of the true one,
      then confirmed against the procedure actually running. A derivation nobody checks and a
      measurement nobody explains are both worth less than the pair.


      
5. Two gradients, deliberately

      
implementedGrad : d/dtheta with the rollout weights and targets DETACHED
                  (this is what backprop through a sampled token computes)
trueGrad        : central differences on the exact expected loss

eps = 0    rel 1.6e-10   cos 1.000000     <- identical, and it must be
eps = 1    rel 9.7e-2    cos 0.992895     <- mostly the right direction, which is the problem

      
The ε=0 row is the control that makes the ε>0
      rows mean something. If the two disagreed there, the discrepancy would be a bug in the
      finite differences rather than a property of scheduled sampling.


      
6. The RNN exists so the backward pass is real

      
h[t]   = tanh(Wx E[in[t]] + Wh h[t-1] + bh)
logits = Wo h[t] + bo
// BPTT by hand; every tensor checked against central differences
dE 8.9e-11  dWx 5.1e-10  dWh 4.1e-10  dbh 2.1e-10  dWo 7.6e-10  dbo 1.9e-10

      
And it reproduces the finding it was built to test: on a 6-mode latch a two-unit RNN runs
      1.13–1.47× worse on its own prefixes across three seeds, while on a 2-mode latch
      — which two hidden units can represent — the ratio is 0.995–1.005 and there
      is no gap at all.


      
7. A fine grid, because a coarse one lies

      
// first version: 3 values of eps, 1 process   -> "it loses at every setting tried"
// this version : 0.05 grid, 90 processes      -> it wins in 28 of them, by up to 31.1%

      
Day 67 nearly shipped an impossibility claim off a coarse grid; the identical mistake was
      available here and the sweep is what caught it. The page now reports both the wins and the
      losses, and the assertion set includes one that would fail if the page went back to
      claiming the cure never works.


      
8. What the tests pin

      
// exposure bias is model error, not a property of the loop
assert(gap(well-specified model) < 1e-12);          // 3.1e-33

// the two loops start identically, and that is exact
assert(|perStepData[0] - perStepFree[0]| < 1e-15);
assert(|perStepData[1] - perStepFree[1]| < 1e-15);

// the derivation, against the procedure
assert(ssFixedPoint(T=2, eps) === (1-eps)*P + eps*m);     // 5.6e-17
assert(ssFixedPoint(T=2, eps=0) === truth);               // teacher forcing is the eps=0 case

// the gradient, both directions
assert(relErr(applied, true) < 1e-6)  at eps = 0;
assert(relErr(applied, true) > 1e-3)  at eps = 0.5;
assert(|applied| < 1e-12 && |true| > 1e-6)  at the fixed point;

// one wrong token, exactly k steps
assert(tv[j] > 1e-6  for j < k);
assert(tv[j] < 1e-12 for j >= k);

// and the cure is allowed to win
assert(a fine sweep is run and its best eps is reported, whatever it is);

      
The pair in the middle is the one worth stealing. Asserting that the applied gradient is
      zero and the true one is not, at the same point, turns "the estimator is
      biased" from a claim into a test that would fail if it were not.
