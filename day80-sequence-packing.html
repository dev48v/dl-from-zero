🧩 Sequence packing — and the mask that makes it correct. Short documents padded to the batch maximum burn most of their compute on padding: on the length distribution here, arrival-order batches are 27.98% real tokens. Packing concatenates documents into one row and lifts that to 99.81%, 3.57× fewer tokens processed. But attention inside a row is global, so packing is wrong by default in two independent ways, and this page runs both bugs as separate configurations and measures them against an unpacked ground truth. 🟢 The identity first: with a block-diagonal mask and position ids that reset per document, the packed row reproduces the unpacked run to 2.22×10⁻¹⁶ — one unit in the last place, across five independently seeded models and every token of every document. 🔴 Drop the mask and the fourth document in the row spends 83.8% of its attention on documents it has never seen (worst single token 94.9%), moving its output by 0.3607. 🔴 Keep the mask but let the position ids run on and the output moves by 0.7607 — a different number, from a different cause. Run both and you get 0.7773, which is neither the sum nor the max. 🔴 🔴 Nothing raises an error, because every attention row still sums to 1 to 4.44×10⁻¹⁶ in all five configurations — a masked softmax renormalises over whatever it is left with, so the shape is right, the loss falls, and the model just learns something slightly wrong.

The ground truth is the unpacked run. Every document is first pushed through the stack on its own, with an ordinary causal mask and positions 0…L−1. 🔴 Both bugs leave the first document in the row bit-identical — exactly 0, not nearly zero. Causal attention cannot look forward, so nothing precedes document one to leak in, and its positions already start at 0 whether or not anyone resets them. If you spot check a packed batch by looking at the first sequence, both bugs are invisible.

1. The identity, and why the tolerance is not zero

The claim is not “close enough”. With the block mask and reset positions, the packed row is computing the same arithmetic as the unpacked run: the same scores over the same keys, the same softmax over the same set, the same value sum. The residual is —, which is one unit in the last place at this magnitude.

It is not exactly zero for one stated reason. A batched attention kernel subtracts a row maximum before exponentiating, and it takes that maximum over the whole causal prefix of the row, not over the current document — a packed row and a lone document therefore subtract different constants. Subtracting a constant from every score leaves a softmax mathematically unchanged, so this is a reassociation, not an error; it moves the last bit and nothing else. The engine deliberately reproduces that kernel behaviour rather than hiding it, and the assertion is max|Δ| ≤ 1e-12, four orders of magnitude of headroom above the measured residual and twelve below the smallest real bug on this page.

2. Leakage is exactly proportional, and here is the identity that says so

Drop the block mask and keep the position reset, and layer one’s inputs are still identical to the unpacked ones — so the own-document scores are the same numbers. The masked softmax then divides by a larger normaliser, and it divides every own-document weight by the same larger normaliser. Writing L for the leaked mass:

a_packed[own] = (1 − L) · a_unpacked[own], measured to —, and therefore ctx_packed = (1 − L)·ctx_unpacked + L·v̄_foreign, so the error is L · |v̄_foreign − ctx_unpacked| — measured against that product to —.

That is where the threshold on the divergence comes from. It is not a number picked to be comfortably passed: it is L×gap, computed per token from quantities the run already produces, and the measured error matches it to the last bit. The largest is —.

5. The compute, including the part packing does not save

🔴 Two honest subtractions from the headline. First, sorting by length before batching already recovers almost all of it: bucketed batches reach — utilisation against packing’s —, so the 3.57× is measured against arrival-order batching, which is the baseline packing is usually sold against but not the only alternative. Sorting is not free either — it correlates batch content with length — but on token count alone it is nearly a tie.

Second, packing does not make attention cheaper unless the mask does. Attention cost is quadratic in the row, so a packed row of — computed densely costs — of the padded baseline — slightly more. It is the block-diagonal structure, exploited by a kernel that skips the off-diagonal blocks, that brings it to —. The mask is not only the thing that makes packing correct; it is the thing that makes it fast.

The row count itself is bounded rather than trusted: a greedy first-fit-decreasing packing must use at least ceil(ΣL / C) rows and at most ceil(ΣL / (C − Lmax)) + 1, which is — here, and the measured count is —.

What this covers, and what it does not

The models are not trained. Weights come from a stated Park-Miller seed, so nothing here says what either bug does to a fitted model’s accuracy — only what it does to the arithmetic, which is the part that can be settled exactly. Positions are a learned absolute table, not RoPE; the reset argument is the same for both (a wrong position id is a false distance either way) but the measured magnitudes would not carry over. There is one attention head and no MLP, and the stack is two layers deep — enough to show the error compounding, not enough to say how it compounds at depth 32. Which of the two bugs is larger is a property of the ratio between the embedding scale and the position scale in this toy, so the ordering is not a general claim; the claim is that both are non-zero, independent, and invisible to the loss. The packing study counts tokens and attention FLOPs, not wall clock: no kernel, no memory traffic, no measurement of an actual block-sparse implementation. And nothing here is about tokenisation or numeric precision — the whole page runs in float64.

How it works

// the only difference between a correct packed row and a broken one
const allow = cfg.block
  ? (i, s) => s <= i && p.docIds[s] === p.docIds[i]
  : (i, s) => s <= i;                  // causal only: the mask bug

const posIds = cfg.reset ? p.local : p.tokens.map((_, i) => i);

// a masked softmax STILL normalises - which is why neither bug throws
for (s...) if (allow(i, s)) { ex[s] = Math.exp(sc[s] - m); Z += ex[s]; }
for (s...) a[s] = ex[s] / Z;

// the leak identity: own weights are scaled by exactly (1 - L),
// so the error is L * |vbar_foreign - ctx_unpacked|, per token.
worstScale = Math.max(worstScale, Math.abs(ap - (1 - L) * au));

Self-check

Runs on load. The load-bearing assertion is the one that must come out zero: a page that only showed two configurations disagreeing would be indistinguishable from a page with a broken slicing index. The identity is checked first, at 1e-12, before any claim of divergence is made — and the divergence thresholds are derived from the run (L×gap, and a multiple of the identity residual) rather than typed in.
