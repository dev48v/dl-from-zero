DEEPLEARNINGFROMZERO · DAY 66

🎭 Attention masks — two masks, one +=, and a bug that trains fine and evaluates wrong. The causal mask stops a position seeing the future; the padding mask stops every position seeing the filler added to make a batch rectangular. They are different shapes — causal is per-position, padding is per-sequence — and the two must be combined, not chosen between — except that measuring it turned up something sharper than the usual advice. With right padding a causal mask already excludes every padded key from every real query, so the padding mask is redundant for decoder self-attention. The leak is total with left padding, which is exactly what decoder-only generation uses, because the prompt has to end at the last position. Get it wrong and the failure is quiet: a model that attends to padding still converges, because padding embeddings drift to whatever makes the loss small, and it only breaks when the batch composition changes at inference. This page implements real scaled dot-product attention and measures the leak in three ways: how much attention mass lands on padding, whether a sequence's output changes when you re-batch it with different neighbours, and what happens at the position everyone forgets — a fully padded row, where masking everything makes softmax divide by zero and the mask that "worked" produces NaN. Pure vanilla JavaScript, one file, offline.

Two masks, and they are not the same shape


      
Causal stops position i attending to position j > i.
      It depends only on positions, so it is one lower-triangular matrix shared by every sequence in
      the batch.


      
Padding stops every position attending to the filler tokens added to make
      a ragged batch rectangular. It depends on the sequence, so it is a different mask per row of
      the batch, and it is a column mask — a padded key is invisible to all queries.


      
causal:  [T, T]     shared, lower triangular
padding: [B, T]     per sequence, broadcast across queries
combined: causal[i,j] AND padding[b,j]


      
They are combined with a logical AND, and the classic bug is passing one of them where the
      other was expected — which type-checks, runs, and trains.


      
The side of the padding decides whether it matters


      
This page was written to say "you need both masks", and measuring it produced something
      sharper. With right padding, a real query at position i < len can
      only attend to j ≤ i < len — so causality has already excluded every
      padded key, and the measured leak from a causal-only mask is exactly 0%. For
      decoder self-attention on right-padded batches, the padding mask is redundant.


      
With left padding it is the opposite: the filler sits at low indices,
      which is precisely where causality lets everything through. A causal-only mask leaks
      55.6% of every real position's attention onto padding, and the same sequence
      gives a different answer depending on what it was batched with.


      

        
And left padding is not the exotic case — it is what decoder-only
        generation uses, because the prompt has to end at the last position for the next
        token to continue it. So the configuration where the padding mask is essential is the one
        running in production, and the configuration where it looks redundant is the one you tested
        during training.

      


      
Why it trains fine anyway


      

        
If padding is attendable, the padding embedding is a free parameter the
        model can use. Gradient descent will happily push it somewhere useful, and the loss goes
        down. The model has learned to use a token that means nothing, and the answer now
        depends on how many of them happen to be in the batch.

      


      
So the failure does not appear in training curves. It appears when batch composition
      changes: a different batch size, a sorted-by-length loader, or single-sequence inference in
      production — and the same input gives a different answer.


      
The test that catches it without labels


      
out_alone  = model([seq])                    # batch of one, no padding
out_padded = model([seq, longer_seq])[0]     # same seq, now padded

assert allclose(out_alone, out_padded, atol=1e-6)


      
Batch invariance is the property. It needs no data, no labels and no training, it runs in
      milliseconds, and it fails loudly on exactly the bug that otherwise ships. This page measures
      it for all four mask configurations.


      
The row everybody forgets


      
Take a padding position, under a causal mask, early in the sequence. Causal blocks
      everything after it; padding blocks everything that is filler. It is entirely possible for a
      row to have no allowed key at all.


      
Softmax over a row of all −∞ is 0/0. You get NaN, and it spreads through the whole
      network on the next matmul.


      
The usual workaround is to fill with −1e9 rather than −Infinity. That does not fix the
      problem; it hides it. Every entry is equally large and negative, so softmax returns a
      uniform distribution over blocked positions — a well-formed row of meaningless
      numbers, which propagates silently instead of announcing itself.


      
The actual fix is to not have that row matter: mask the output at padded query
      positions, or clamp fully-masked rows to zero after the softmax. Both are one line, and both
      are more honest than choosing a fill constant that makes the NaN go away.


      
Two more traps worth naming


      
    
        
  • Left padding versus right padding. For a decoder generating text, the
        prompt must end at the last position, so left padding is correct — and it inverts every
        index you were computing from sequence length.
    • 
        
  • The mask must reach the loss. Masking attention and then averaging the
        loss over all positions puts padded positions back into the objective. Two different masks,
        two different places, and fixing one does not fix the other.
    • 
      


    

  






  

    


      
🔨 How it is built


      
1. Real scaled dot-product attention

      
function attention(Q, K, V, allowed){
  const T = Q.length, d = Q[0].length, out = [];
  for (let i = 0; i < T; i++){
    const scores = [];
    for (let j = 0; j < T; j++)
      scores.push(allowed(i, j) ? dot(Q[i], K[j]) / Math.sqrt(d) : -Infinity);
    const w = softmax(scores);
    out.push(weightedSum(w, V));
  }
  return { out, weights };
}

      
The / Math.sqrt(d) is not decoration: without it the scores grow with head
      dimension and softmax saturates, which would make every mask look equally effective because
      one weight is 1.0 and the rest are 0.


      
2. The masks, as predicates

      
const causal  = (i, j) => j <= i;
const padding = (len) => (i, j) => j < len;            // a COLUMN rule
const both    = (len) => (i, j) => j <= i && j < len;  // AND, not "pick one"

      
Writing them as predicates makes the combination obviously a conjunction. As tensors it is
      a broadcast, and a broadcast that silently succeeds with the wrong shape is where the bug
      lives.


      
3. Softmax that reports rather than hides

      
function softmax(scores){
  const max = Math.max(...scores);
  if (!isFinite(max)) return scores.map(() => NaN);   // EVERY key blocked
  const e = scores.map(s => Math.exp(s - max));
  const z = e.reduce((a, b) => a + b, 0);
  return e.map(v => v / z);
}

      
The early return is deliberate. A fully masked row is a real condition and the honest
      answer is "undefined" — so the page can count NaN rows and show you that the −1e9 workaround
      returns a tidy uniform distribution instead, which is the more dangerous outcome.


      
4. The batch-invariance test

      
const alone  = attention(Q.slice(0, len), K.slice(0, len), V.slice(0, len), maskFor(len));
const padded = attention(Q, K, V, maskFor(len));      // same seq, extra padded slots

let worst = 0;
for (let i = 0; i < len; i++)
  for (let k = 0; k < d; k++)
    worst = Math.max(worst, Math.abs(alone.out[i][k] - padded.out[i][k]));

      
Only the real positions are compared — the padded rows are allowed to be anything, because
      nothing downstream should read them. The correct mask gives 0 here, exactly,
      and every incorrect one does not.


      
5. What the tests pin

      
// the mask is the mask
assert(causalWeights[i][j] === 0) for all j > i;
assert(paddingWeights[i][j] === 0) for all j >= len;

// rows are distributions, except where they cannot be
assert(|sum(row) - 1| < 1e-12) for every row with at least one allowed key;

// THE property
assert(rebatchDelta("both") === 0);
assert(rebatchDelta("causal") > 0);      // and the wrong ones really do differ
assert(rebatchDelta("none")   > 0);

// and -1e9 is not a fix
assert(isNaN(softmax(allBlockedWithInfinity)[0]));
assert(!isNaN(softmax(allBlockedWithBigNegative)[0]));
assert(isUniform(softmax(allBlockedWithBigNegative)));

      
The last three are the ones worth stealing. They assert that the workaround
      produces well-formed garbage — which is the whole reason it is worse than the NaN.
