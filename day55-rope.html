DeepLearningFromZero · Day 55

🔄 RoPE (Rotary Position Embeddings) — self-attention is order-blind: the raw QKᵀ scores are pure content dot-products, so a Transformer has to be told where each token sits. Day 29’s sinusoidal recipe adds a positional vector to every token; ALiBi (Day 54) adds a distance bias to the scores. RoPE (Su et al., 2021 — RoFormer) does neither — it encodes position by rotating the query and key. Split each d-dim vector into d/2 two-dimensional pairs, and for a token at position p spin pair i by an angle θ = p·ωi using a fixed per-pair frequency ωi = base−2i/d (a geometric ladder from fast to slow, base = 10000 in LLaMA). The magic is a plain rotation identity: the dot product of two rotated vectors depends only on the difference of their angles — R(m&theta)ᵀR(n&theta) = R((n−m)&theta) — so the attention score qm·kn collapses to a function of the relative offset m−n alone, even though each vector was rotated by its absolute position. High-frequency pairs spin fast (fine, local position); low-frequency pairs barely move (coarse, long-range) — a built-in multi-scale code, and because rotation preserves length it never rescales Q or K. That relative-offset property is why RoPE powers LLaMA, GPT-NeoX, PaLM, Mistral and kin, and why it stretches to long context so cleanly — scale the base or interpolate positions (NTK-aware / position-interpolation) and the wavelengths lengthen without meeting an unseen absolute index. Below: watch the 2D sub-planes rotate as you slide the query position m and key position n, see the full score q·k stay glued to constant diagonals of a (m,n) heatmap (it depends only on m−n), and drag the base / head-dim across the frequency schedule ωi = base−2i/d — rotation and dot products implemented by hand, no libraries.

Three ways to give a Transformer position
Sinusoidal · Day 29
ABSOLUTE, added to the inputs: x′ = x + PE(p). A sin/cos ladder or learned table; extrapolates poorly past the trained length.
ALiBi · Day 54
RELATIVE, added to the scores: −m·(i−j). A fixed per-head bias; nothing rotates, best raw length-extrapolator.
RoPE · today
RELATIVE, applied by rotating Q & K: R(pω). Score becomes a function of m−n; preserves norm; scales to long context.

🔨 Build it yourself

    
RoPE is a rotation bolted onto ordinary attention: no added position vector, no learned parameters, just spin each 2D pair of Q and K by an angle set by its position. We’ll build it up: the 2D rotation, the frequency schedule, RoPE on a whole vector, the relative-offset property that falls out of the rotation identity, the full RoPE attention, and the base-scaling trick that unlocks long context.

    
    
      
  1. 
        
    1
    Rotate a 2D pair — and it keeps its length
    
        
    RoPE works on 2D sub-vectors. Rotating (x,y) by angle a is the 2×2 rotation matrix. A rotation is orthogonal, so it preserves the norm: |R(a)v| = |v|. That is why RoPE never rescales Q or K — it only turns them.
    
        
    import numpy as np

def rot2(x, y, a):                 # rotate the pair (x, y) by angle a
    c, s = np.cos(a), np.sin(a)
    return x*c - y*s,  x*s + y*c   # R(a) @ [x, y]

v = np.array([0.8, -0.3])
w = np.array(rot2(v[0], v[1], 1.234))
assert np.allclose(np.linalg.norm(w), np.linalg.norm(v))   # norm preserved

    The frequency schedule — a geometric ladder
    
        
    Pair i rotates at its own rate omega_i = base^(-2i/d). Pair 0 spins at 1 rad/step (fine, local); later pairs slow geometrically toward 1/base (coarse, long wavelength 2*pi/omega). base = 10000 in the original RoPE / LLaMA.
    
        
    def rope_freqs(d, base=10000.0):
    i = np.arange(d // 2)                 # one frequency per PAIR
    return base ** (-2.0 * i / d)         # omega_i, geometric ladder

rope_freqs(8)
# [1.0, 0.1, 0.01, 0.001]                # fast -> slow
# wavelengths 2*pi/omega : 6.28 .. 6283  # local -> long-range

  3. 
        
    3
    Apply RoPE to a whole vector at position p
    
        
    Split the d-vector into d/2 pairs and rotate pair i by p * omega_i. Nothing is added to the vector — each pair is turned. The same content vector at a different position is the same vector, spun by a different angle.
    
        
    def rope(v, p, base=10000.0):
    d = len(v); w = rope_freqs(d, base)
    out = v.copy()
    for i in range(d // 2):
        a = p * w[i]
        out[2*i], out[2*i+1] = rot2(v[2*i], v[2*i+1], a)
    return out                              # q_p = R(p) v  (norm unchanged)

    The relative-offset property — the whole point
    
        
    A dot product of two rotated vectors depends only on the difference of their angles, because R(m*t)^T R(n*t) = R((n-m)*t). So rope(q,m) · rope(k,n) is a function of m-n alone — equal for (5,3) and (7,5), though each vector was rotated by its absolute position.
    
        
    def score(q, k, m, n, base=10000.0):
    return rope(q, m, base) @ rope(k, n, base)

q = np.random.randn(8); k = np.random.randn(8)
assert np.allclose(score(q, k, 5, 3), score(q, k, 7, 5))   # same offset 2
assert np.allclose(score(q, k, 9, 9), q @ k)               # offset 0 -> raw q.k

    5
    RoPE attention — rotate Q and K, then the usual QKᵀ
    
        
    Rotate every query and key by its position before the dot products; V is untouched, and nothing is added to the inputs. The resulting score matrix is automatically relative — entry (m,n) only ever sees m-n.
    
        
    def rope_attention(Q, K, V, base=10000.0):
    N, d = Q.shape
    Qr = np.stack([rope(Q[p], p, base) for p in range(N)])   # rotate queries
    Kr = np.stack([rope(K[p], p, base) for p in range(N)])   # rotate keys
    scores = (Qr @ Kr.T) / np.sqrt(d)                        # relative by construction
    scores[np.triu_indices(N, 1)] = -np.inf                  # causal mask
    A = np.exp(scores - scores.max(1, keepdims=True))
    A /= A.sum(1, keepdims=True)
    return A @ V, A

    6
    Long context — scale the base, stretch the wavelengths
    
        
    Push a model past its trained length and the fast pairs alias. Two fixes reuse the same code: position interpolation squeezes positions (p → p/s) so old angles cover new lengths; NTK-aware scaling raises the base so the slow pairs stretch while the fast ones stay sharp. Both only touch the schedule — the rotation is unchanged.
    
        
    # position interpolation (PI): squeeze positions into the trained range
def rope_pi(v, p, s):     return rope(v, p / s)          # s = new_len/train_len

# NTK-aware: grow the base so low frequencies stretch, high stay put
def rope_ntk(v, p, s, d, base=10000.0):
    return rope(v, p, base * s ** (d / (d - 2)))

# both keep the SAME relative-offset property, just with longer wavelengths

🎉 Day 55 of DeepLearningFromZero done.
RoPE gives a Transformer position by rotation instead of addition: split Q and K into d/2 2D pairs and spin pair i by p·ωi with the geometric schedule ωi=base−2i/d. Because a dot product of two rotated vectors depends only on the difference of their angles (R(mθ)ᵀR(nθ)=R((n−m)θ)), the score qm·kn is a function of the relative offset m−n alone — the Toeplitz stripes you saw — even though each vector was rotated by its absolute position. High-frequency pairs encode fine local order, low-frequency pairs encode coarse long-range order, and because rotation preserves norm it never rescales Q or K. Unlike sinusoidal (absolute, added to inputs) or ALiBi (relative, a bias added to scores), RoPE is relative and applied by rotating Q/K — which is why it powers LLaMA, GPT-NeoX, PaLM and Mistral and stretches to long context via base/position scaling (NTK, PI). 👉 Tomorrow, Day 56: Mixture-of-Experts — route each token to a few expert MLPs for huge capacity at a cheap per-token cost.
